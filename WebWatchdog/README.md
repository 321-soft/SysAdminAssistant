# Быстрая настройка из Assistant

Настройки → Внешний контроль сервера → Создать ZIP для хостинга. Выбери Beget, shared-хостинг или собственный Linux-сервер. Укажи реальные пути, PHP CLI и URL; проверь назначения перед сохранением. Архив содержит готовые private/config.php, три приватных PHP-файла и public/heartbeat.php с заполненным require. START-HERE.txt содержит точные пути, init/test/status и cron; конфиг содержит ключ и текущие настройки Telegram. Экспорт разрешён только главному администратору. ZIP с секретами не публиковать.

Настрой сайт и cron, затем включи сигналы в итоговом окне. Существующий серверный ключ сохраняется при повторном экспорте. Экспорт сам не меняет рабочую настройку. Отмена «Сохранить как» не делает запрос на сервер.

Для Beget предлагается `/usr/local/bin/php8.4`; сначала проверь этот путь в панели. Не используй просто `php`: CLI по умолчанию может быть старым и завершаться с кодом 255. В мастере все пути редактируются. PHP сайта также должен быть 8.1+. Для других хостингов нет универсального PHP-пути: бери его из панели. Приватные файлы могут лежать в родителе public_html — отдельный каталог для состояния не нужен.

Далее — ручной вариант, если мастер не используется.

# PHP-наблюдатель SysAdmin Assistant

Это самостоятельный наблюдатель на твоём хостинге вне ДЦ. Никаких сторонних платформ мониторинга. Можно использовать того же Telegram-бота и тот же чат, что в Assistant. Подключение не требует опроса сообщений бота и не мешает текущим уведомлениям.

## Требования

PHP 8.1 или новее, 64-битный; расширения json, hash и curl; HTTPS с действительным сертификатом; cron каждые 5 минут; PHP CLI для cron. Хостинг должен разрешать исходящий HTTPS к api.telegram.org. Клиентский Windows и хостинг должны иметь точное время (подпись принимается в пределах ±120 секунд).

Нужен доступ к приватному каталогу вне public_html/www/document root. Не клади config.php или state.json в публичную папку даже с расчётом на .htaccess. На хостинге без приватного каталога эту схему сначала надо адаптировать с администратором хостинга.

PHP CLI в командах ниже — пример `/usr/bin/php8.4`. Сначала сверить путь у хостера; для Beget обычно используется `/usr/local/bin/php8.4`. Проверить `<путь-PHP> -v`. При коде 255 добавить `-d display_errors=1 -d error_reporting=-1` перед путём worker.php; проверить версию и curl.

## 1. Разложить файлы

Пример путей; USER замени на свой логин хостинга:

- /home/USER/saa-watchdog/ — сюда lib.php, receiver.php, worker.php и config.example.php из этого пакета. Это НЕ публичная папка.
- Отдельная папка состояния не нужна: `state_directory => __DIR__` хранит state.json рядом с приватным config.php. PHP сайта и cron должны иметь запись в этот каталог.
- /home/USER/public_html/heartbeat.php — только маленький файл из public/heartbeat.php.

В публичном heartbeat.php замени абсолютный путь require на /home/USER/saa-watchdog/receiver.php. Через браузер файлы приватного каталога не должны открываться.

## 2. Создать config.php

Скопируй config.example.php рядом в config.php. Установи chmod 600 для config.php, 700 для приватных каталогов. PHP веб-сайта и cron должны иметь права записи в каталог состояния. Если сайт и cron работают разными пользователями — настрой минимальную общую группу/ACL у хостера, не права 777.

Заполни:

- server_id: assistant-server (латиница/цифры/_/-, до 64 символов). В клиенте Assistant будет ровно такой же ID.
- name: понятное название сервера для сообщений.
- secret: общий секрет из 64 hex-символов. Мастер «Настройки → Создать ZIP для хостинга» создаёт ключ автоматически. При ручной настройке сгенерируй 32 случайных байта криптографическим генератором и представь их как 64 hex-символа. Сохрани его в config.php и затем введи в Assistant. Не публикуй ключ и не присылай его в чат.
- telegram_token: токен твоего бота. Хранится только в приватном конфиге сайта; для этой функции в Assistant его повторно вводить не требуется.
- telegram_chat: числовой ID чата/группы (обычно отрицательный у группы). Бот должен быть добавлен в группу и иметь возможность писать. Для личного чата сначала нажми Start у своего бота. Токен — не Chat ID.
- state_directory: `__DIR__` — этот же приватный каталог. Дополнительную папку создавать не нужно.
- maintenance: false.

Для другого сервера используй отдельный конфиг/каталог состояния и ID, не один state.json на несколько серверов.

## 3. Проверить запуск и Telegram

В консоли хостинга:

```
/usr/bin/php8.4 /home/USER/saa-watchdog/worker.php init
/usr/bin/php8.4 /home/USER/saa-watchdog/worker.php test
/usr/bin/php8.4 /home/USER/saa-watchdog/worker.php status
```

Уточни реальный путь PHP CLI в панели хостинга; например /usr/bin/php8.3. Команда test должна отправить одно тестовое сообщение. Пока тест не получен, не считай уведомления настроенными. Команда test не подделывает сигнал сервера и не меняет состояние тревоги.

## 4. Настроить cron

Если панель имеет пять полей расписания:

```
*/5 * * * *
```

Команда задачи:

```
/usr/bin/php8.4 /home/USER/saa-watchdog/worker.php check >> /home/USER/saa-watchdog/cron.log 2>&1
```

В обычном crontab полная строка:

```
*/5 * * * * /usr/bin/php8.4 /home/USER/saa-watchdog/worker.php check >> /home/USER/saa-watchdog/cron.log 2>&1
```

Cron запускается на хостинге сайта, не на сервере Assistant. Это важно: при падении ДЦ проверка должна продолжать работать. Не заменяй cron открытием PHP по ссылке: worker доступен только из CLI.

Проверь время появления строк в cron.log. Настрой ротацию журнала по возможностям хостинга. Дубли задач не нужны: блокировка защищает состояние от одновременной работы.

## 5. Настроить Assistant

Обнови сервер и клиент. Настройки → Сервер → Контроль доступности сервера:

- HTTPS-адрес: https://твой-домен/heartbeat.php. Без query-параметров, логина и редиректа.
- ID: ровно server_id из config.php.
- Общий ключ: secret из config.php.
- Включи отправку и сохрани.

Сигнал отправляется раз в минуту, независимо от запуска клиента. Через минуту снова открой настройки: должно появиться время подтверждённого сигнала. `worker.php status` на сайте должен показать свежее last_seen_utc. HTTP 200 само по себе недостаточно: сервер проверяет подпись ответа.

PHP-приёмник требует HTTPS. За доверенным прокси настрой у хостера корректный HTTPS-флаг для PHP. Код намеренно не доверяет произвольному X-Forwarded-Proto от клиента. Ошибка 400 на HTTPS обычно требует проверить именно конфигурацию прокси/хостинга; не отключай проверку TLS.

## 6. Проверить реальную тревогу

В удобное время останови службу Assistant вручную. Не закрывай только клиент — это не остановит серверные сигналы. Через 5–10 минут после последнего сигнала должен прийти красный статус. Следующий cron не должен повторять уже доставленную тревогу. Запусти службу, дождись свежего last_seen_utc; при ближайшем cron (до 5 минут) придёт зелёное восстановление.

Наблюдатель не выполняет никаких действий на сервере, не перезапускает службы и не требует входящих портов в ДЦ.

## Обслуживание и ошибки

Плановая работа: maintenance=true в config.php. Сигналы продолжают приниматься, уведомления приостановлены. После false даётся защитный интервал; зелёное восстановление возможно только после настоящего свежего сигнала. Галка в Assistant сама по себе не ставит сайт на паузу: если её снять без maintenance, наблюдатель сообщит об отсутствии сигналов.

Время последнего сигнала хранится на диске сайта. Перезапуск PHP/cron не забывает уже отправленную тревогу. При сбое доставки состояние не помечается как доставленное, выполняются повторные попытки с учётом ограничения Telegram. Не удаляй state.json и не меняй каталог ради устранения красной лампы: сначала проверь причину.

При повреждённом состоянии проверка останавливается с ошибкой, а не рисует зелёный статус. Сохрани файл для диагностики, проверь права/место на диске и восстанови корректную копию. `init` не затирает существующее состояние.

Обычная работа даёт одно сообщение о потере связи и одно о восстановлении. Редкий сетевой обрыв после принятия сообщения Telegram, но до получения ответа, либо сбой процесса до записи состояния может дать повтор при следующей попытке: Bot API не предоставляет ключ идемпотентности для sendMessage. Строгое exactly-once не обещается.

Если перестанет работать сам cron/сайт/Telegram, этот наблюдатель не сможет гарантировать доставку. Его работа также требует периодической проверки. Сообщения наблюдателя не управляются закрепом Assistant; чужие закрепы не меняются.

## Что защищено

Пакет содержит версию протокола, ID, время, случайный nonce и HMAC-SHA256. Общий ключ не передаётся. Повторы и слишком старые/будущие запросы отвергаются. Подписанный ответ связан с конкретным запросом. Состояние записывается атомарно под блокировкой. Вложения, устройства, имена пользователей и пароли на сайт не отправляются. Сайт видит публичный IP сервера, ID и время сигнала.

При смене общего ключа обнови его на обеих сторонах. Это не сертификат сервера Assistant; его автоматическое продление не требует менять ключ PHP-наблюдателя.
