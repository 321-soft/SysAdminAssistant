# Выпуск 0.46.12 — сбор оборудования

Дата: 23.11.2026.

## Что изменено

Сборщик больше не использует WbemScripting.SWbemLocator, Reflection.InvokeMember и автоматическое перечисление SWbemObjectSet. Подключение, запрос, получение следующей строки и чтение свойства выполняются через документированные нативные интерфейсы WMI. Запросы остаются локальными и только для чтения.

- Локальное подключение и настройка прокси, типизированные параметры; нет optional VARIANT-контекста.
- Правильный порядок аргументов нативного ExecQuery: язык WQL, затем запрос.
- Обработка WBEM_S_FALSE вместе с последним объектом, исходных HRESULT и таймаутов перечисления.
- Освобождение каждого объекта и перечислителя при успехе, ошибке свойства и ошибке настройки прокси.
- Проверка указателей перед обращением; ограничение количества объектов и ожидания.
- Преобразование CIM unsigned-значений: флаг встроенного дисплея не теряется из-за отрицательного Int32.
- Диагностика содержит код, пространство имён, класс и этап WMI в пределах существующего лимита 200 символов.

## Проверка

Полный набор: 2070 спецификаций прошли. Агент, клиент, сервер, установщики и WindowsUiSpecs скомпилированы в Linux. Последний реальный скриншот относится к прежнему SWbem-пути; подтверждения успешного сбора новой реализацией на Windows ещё нет.

Модельные проверки вызывают управляемые реализации таблиц интерфейсов: проверены аргументы, обработка последнего объекта, ошибка свойства, освобождение ресурсов, сохранение HRESULT, неверный указатель и ограничение ожидания. Это не проверка реального COM-провайдера Windows и не замена ей.

## Проверка на ПК без изменения службы

В архив включена скомпилированная утилита verification/WmiProbe. На Windows с .NET 10 x64 запустите RUN.cmd. Она сначала должна прочитать Caption из Win32_OperatingSystem, затем характеристики и периферию тем же сборщиком, что агент. Результат — hardware-probe.txt рядом с утилитой. Служба и её регистрация не изменяются. Утилита ничего автоматически не отправляет. Контекст пользователя отличается от LocalSystem службы.

Для проверки через исходники на Windows:

```bat
dotnet run --project tests\SysAdminAssistant.WindowsUiSpecs -- --hardware-smoke
```

Smoke-тест теперь требует реального свойства ОС и доступного результата периферии. Исчезновение только DISP_E_TYPEMISMATCH больше не считается успехом.

## Развёртывание

Изменение относится к агентскому сборщику. Для получения выпускных пакетов запустите PUBLISH.bat на Windows; для автоматической доставки агента используйте серверный комплект с вновь собранным и подписанным пакетом/MSI. Существующие регистрации и ключи не нужно отзывать. Сама самостоятельная утилита может использоваться до обновления службы.

Записанные отдельно изменения сортировки, стабильной панели действий и размещения деинсталлятора остаются в плане; в этой срочной правке сборщика они не реализованы. Предупреждения NU1510/IL3000 также не устранены этим изменением. Windows-публикация и установщики в данной среде не выполнялись.
