# Источники почтовых событий

Откройте **Настройки → Почта и отчёты → Источники почты** или **Справочник предупреждений → Источники почты**. Справочник общий для всего сервера: один источник можно использовать для писем от нескольких устройств, а одно устройство может присылать уведомления от разных программ.

1. Нажмите **Добавить источник**. Укажите устойчивые фразы в адресе отправителя, теме или теле. Внутри поля фразы перечисляются через точку с запятой или с новой строки; достаточно совпадения одной фразы. Галочка определяет, должны ли совпасть все заполненные поля. Регистр не учитывается.
2. На вкладке **События** добавьте отдельное правило для каждого исхода. Укажите название, условия, уровень и подсказку. «Обычное событие» подходит для уведомлений, которые не являются отчётами о бэкапе.
3. На вкладке **Проверка** вставьте письмо и посмотрите результат перед сохранением. Если подходят несколько источников или событий, письмо останется на проверке. Тест не сохраняет письмо и не отправляет уведомления.
4. При необходимости настройте привязку к устройству или заданию отдельно. Распознанные события без цели видны в **Почта и отчёты → Без привязки**. При конфликте правил привязки программа не выбирает устройство автоматически.

В очереди **Нераспознанные** можно выбрать письмо и нажать **Создать источник по письму**. Отправитель и тема подставляются в редактор, текст доступен на вкладке проверки. Уберите из условий даты, номера и другие меняющиеся части. После сохранения можно повторить анализ только этого письма. Новые правила применяются к новым письмам; старая очередь автоматически не пересматривается.

**Скачать шаблон JSON**, **Импорт JSON** и **Экспорт выбранного** позволяют переносить определения. Импорт открывает редактор для проверки и сохранения. Файл содержит только определение источника и правила событий; проверьте, что в написанных вручную фразах и рекомендациях нет конфиденциальных данных. Встроенные словари доступны через отдельную кнопку в этом же окне.

Для win-acme используйте реальные письма об успехе и ошибке как образцы. Универсальные признаки не включены: формулировки зависят от настроенного шаблона письма.

При обновлении с 0.42.17 сохраните копию базы и настроек, затем обновите сервер и клиент. Миграция SQLite или SQL Server добавляет поле правил событий, существующие отчёты, словари и привязки сохраняются. У старых устройств сохранённое значение поля «Почтовая система» больше не определяет источник. Для писем, которые зависели от этого поля, настройте источник по образцу.

## Пример: предупреждения от нескольких DSM

Откройте существующий профиль **DSM → Отдельные правила → Добавить отдельное правило**. Назовите его «Мало места на томе», в поле **Текст содержит** укажите `заканчивается доступная емкость; заканчивается доступная ёмкость`, оставьте тему пустой. Укажите уровень **Предупреждение** и результат **Обычное событие**. Сохраните правило и профиль.

Общие условия и словарь уровней менять не нужно. При совпадении письмо распознаётся как DSM с указанным уровнем. Остальные письма разбираются как прежде. Проверьте примеры на вкладке **Проверка**; для старого письма нажмите **Проверить выбранное письмо**.

## Числовые условия

В редакторе события откройте «Числовые условия» и нажмите «+» в нужном уровне. Для строки
`Емкость - Доступное пространство: 1893.98 ГБ (8.84%)` задайте фразу `Доступное пространство:`,
положение «число перед текстом», текст `%` и порог, например `< 10`. Для проверки объёма вместо `%` укажите `ГБ`.
Используйте точку или запятую в десятичной дроби.

Достаточно одного совпадения в пределах уровня. Если сработало несколько уровней, применяется самый высокий.
Если у события есть текстовые условия, они также должны выполняться. Без числовых условий действует уровень из настроек события.
При нескольких найденных числах по умолчанию условие не срабатывает; если подходит любое из них, включите «Любое совпадение».
Вкладка «Проверка числа» показывает извлечённое число или причину, по которой условие не сработало.
