# Web, SSH и RDP · 0.34.0 TEST

Обнови сервер и клиент одной версии. В карточке устройства нажми «Настроить подключения»:

- Web / WebFig: полный URL, например https://192.168.20.1:8443/webfig/. Он не связан с портом RouterOS REST API. HTTP тоже допустим при явной настройке.
- SSH: IP/DNS без URL и порта, порт (обычно 22), необязательный логин.
- RDP: IP/DNS, порт (обычно 3389), необязательный логин, в том числе DOMAIN\user.

Поставь галочки нужных способов и сохрани. Ненастроенные кнопки неактивны. У MikroTik кнопки находятся в карточке «Состояние и события», на верхней панели; Web открывает WebFig в браузере по умолчанию. Параметры меняют пользователи с правом изменения соответствующего раздела «Устройства» или «Коммутаторы / сеть».

Подключения запускаются **на компьютере клиента Assistant**. Сервер и агент не являются прокси и не выполняют SSH/RDP-команды. Web использует браузер по умолчанию. SSH запускает штатный Windows OpenSSH из системного каталога; если клиент OpenSSH отсутствует, появится понятное сообщение. Устанавливать его нужно на рабочем компьютере, не на сервере мониторинга. RDP открывает временный .rdp-файл через приложение, назначенное для этого расширения (обычно mstsc).

Пароли здесь не хранятся: вводи их во внешнем клиенте или используй прежний менеджер паролей. В URL нельзя помещать логин/пароль вида user:password@host; не сохраняй в URL секретные токены. URL, адреса и имена пользователей — обычные метаданные устройства, доступные читателям его раздела. В SSH не передаётся командная строка shell; аргументы формируются отдельно. Проверка сертификатов и ключей хостов не отключается.

RDP-файл содержит только адрес, порт, необязательное имя пользователя и запрос учётных данных. Временные файлы хранятся в LocalAppData\SysAdminAssistant\RdpConnections; файлы старше недели удаляются при следующем запуске RDP. Секретов в них нет. Настройки постоянных подключений хранятся в БД с устройством и сохраняются при переносе БД. Excel-обновление существующего устройства не сбрасывает их; отдельные столбцы подключений в Excel не добавлялись.

Сборка через PUBLISH.bat. Сделай обычную резервную копию перед штатным обновлением сервера. В SQLite/SQL Server добавляется поле ConnectionsJson с пустым значением для прежних устройств; старые данные не удаляются. Обновление агента для этих кнопок не требуется. Исправление systemd из 0.33.1 и связь паролей с сервисами сохранены.

## Исправление теста доступа к паролям

В NetworkSpecs тест Service link never bypasses other owner vault restriction использовал bobClient после отзыва его сеанса изменением прав. Он ожидал 403, но старый сеанс должен получать 401. Используется уже вошедший и разблокированный bobReader; отдельная проверка подтверждает актуальность сеанса и чтение собственной записи. Требование отказа 403 для чужого пароля сохранено, а не заменено приёмкой любого сбоя.

Полный Windows NetworkSpecs запускается VERIFY.cmd/PUBLISH.bat на Windows. Здесь он скомпилирован, но не исполнялся. Отдельный ServiceAccessChecks исполнил реальный OrganizationVault.List/Read с текущим пользователем и связью с сервисом: чужие метаданные не выдаются, чужой секрет запрещён до криптографической обработки. Ключи и шифрование Vault ради исправления теста не изменялись.
