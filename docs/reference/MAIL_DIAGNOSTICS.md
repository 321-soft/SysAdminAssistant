# Почему не отображаются письма

Проверки выполняет сервер, а не компьютер клиента. Приложение не является полноценным почтовым клиентом: оно сохраняет принятые отчёты и не показывает весь INBOX без фильтрации.

1. Настройки → Почта / IMAP → Почтовые ящики → Изменить → «Проверить подключение к ящику». Проверяются реальные несохранённые адрес, порт, логин и папка. Проверка не сохраняет форму. При успехе видны TLS, вход, папка и число писем.
2. Сохрани ящик, включи «Принимать отчёты». Для первоначальной проверки выбери «Все письма»: уже прочитанные письма не попадут в поиск «Только непрочитанные».
3. Для обычных отчётов укажи точные домены From, по одному на строку, например example.test. Не адрес получателя и не полный email. Поддомены отдельно. Пустой список блокирует обработку с явной ошибкой.
4. Нажми «Проверить почту сейчас» в Отчётах или Настройках. Это запуск в очередь; сообщение о запуске не означает завершение. Открой «Диагностика почты» и обновляй результат.
5. Смотри Отчёты → Все и Нераспознанные. Для неизвестного источника и письма без правила SQL-задание не требуется. Ошибки формата DMARC находятся в DMARC → Ошибки DMARC.

## Как понимать результат

| Показатель | Что проверять |
| --- | --- |
| Проверок ещё нет | Служба запущена, ящик сохранён и включён; запусти проверку и обнови результат |
| TLS-соединение / ошибка | DNS и доступ сервера к IMAP, правильный TLS-порт (обычно 993), сертификат, системное время |
| Вход в ящик / ошибка | Логин, пароль приложения почтового провайдера, разрешение IMAP. Пароль вводится в форме, передавать его в чат не нужно |
| Открытие папки / ошибка | Точное IMAP-имя папки, права на неё; начни с INBOX |
| Найдено 0 | Не та папка, режим только непрочитанных; у DMARC также поиск темы DMARC |
| Уже учтено | Эти UID уже импортированы или удалены по сроку хранения. Повторный опрос не дублирует их |
| Фильтр отправителя/темы | Сверь домен From со списком. Обычный ящик исключает темы со словом DMARC; DMARC требует подтверждённого полного адреса и темы DMARC |
| SPF/DKIM отклонено | При включённой проверке нужны оба pass от доверенного принимающего MTA, правильный authserv-id и подтверждённая очистка поддельных заголовков. Это не повторный расчёт подписей приложением |
| Без текстового тела | Вложения обычных отчётов намеренно не читаются. Теперь заголовок и объяснение сохраняются в нераспознанной очереди |
| Без заголовков | Сервер IMAP не вернул Envelope запрошенного UID; письмо могло быть удалено другим клиентом во время опроса |
| Без подходящего содержимого | Для DMARC не найден допустимый XML/архив. Обычное письмо не превращается автоматически в DMARC |
| Принято, отчётов 0 | Возможна дедупликация по содержимому DMARC или уже существующий результат. Проверь старые записи и дату |
| Ящик уже проверяется | Активен другой цикл/процесс; временная блокировка истекает через две минуты без продления |

На подготовленных ранее снимках были включены «Все письма» и мониторинг, а SPF/DKIM был выключен. Поэтому эти три настройки сами по себе не объясняют именно тот случай. Исправлены найденные дефекты кода: зависимость IMAP от общей галочки мониторинга, выбор случайной сводки вместо точного UID, обход старых писем раньше новых, молчаливый пропуск без текстовой части и отсутствие промежуточных результатов. Проверка на рабочем IMAP-сервере ещё нужна.

Чтение остаётся read-only, флаг прочтения не меняется. Защита TLS, фильтры допуска и лимиты вложений не отключены. Полные письма автоматически не скачиваются.
