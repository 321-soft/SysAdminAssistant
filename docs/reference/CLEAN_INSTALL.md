# Удаление старой версии и чистая установка 0.6

Для новой установки нужны пустые папки и новая база. Для существующей 0.6 используй обновление установщиком по ../UPDATES.md, деинсталлятор не нужен.
Новые пути по умолчанию:
- C:\Program Files\SysAdmin Assistant Server 0.6
- C:\ProgramData\SysAdminAssistantServer-0.6
- служебная учётная запись SysAdminSvc06
- служба SysAdminAssistantServer
- формат конфигурации 6, схема серверной базы 7.

## Мастер удаления

Запусти UNINSTALL_SERVER.cmd от имени администратора **из отдельной распакованной папки**. .NET SDK для этого мастера не нужен: он использует Windows PowerShell и Windows Forms.
REMOVE_SYSADMIN_SERVER_ALL.bat теперь открывает тот же мастер, а не выполняет удаление всего одним общим подтверждением.
ExecutionPolicy Bypass применяется только к текущему запуску PowerShell; политика системы не меняется.

Поиск использует зарегистрированную службу, стандартные папки ProgramData/LocalAppData и Program Files версий 0.3–0.6. Нестандартную папку с server.json и settings.json можно добавить вручную.
Для каждого сохранённого SQL-подключения показываются SQL-сервер, база, папка настроек и результат проверки.
Для SQLite показывается полный путь; дополнительные SQLite-файлы в корне папки установки выводятся отдельными строками.
Список не является поиском всех SQL-баз на всех серверах: базы без конфигурации и чужие профили Windows автоматически не обходятся.

Изначально все флажки удаления сняты. Для каждой выбранной базы запрашивается отдельное подтверждение, затем итоговый список.
SQL-база удаляется только при успешном подключении и наличии таблиц SysAdmin Assistant. Системные базы запрещены.
Если секрет подключения не расшифровывается или SQL недоступен, база остаётся непроверенной, удалить её через мастер нельзя.
Если несколько конфигураций указывают на одну базу, необходимо выбрать их все, иначе удаление блокируется.

Отдельно можно выбрать удаление папок программы/данных и служебных учётных записей выбранных установок.
Папка с невыбранной базой, дополнительным невыбранным файлом базы или резервной копией не удаляется.
Учётка удаляется только с маркером принадлежности программе и при отсутствии использующих её служб; учётки сохранённых установок остаются.
.NET runtime, клиент и невыбранные базы сохраняются.

После последнего подтверждения мастер останавливает службу. Сначала удаляются выбранные базы, затем регистрация службы, правило firewall, выбранные учётки и папки.
При ошибке процесс прекращается. Удаление НЕ является общей транзакцией: ранее удалённые базы автоматически не восстанавливаются. Мастер не создаёт резервную копию. Если данные нужны, сохрани их заранее средствами SQLite/SQL Server и скопируй настройки.
При частичной ошибке повторно открой мастер. Если Windows удерживает удалённую службу, закрой services.msc либо перезагрузи сервер.

## Новая установка

Запусти SETUP_SERVER.cmd из подготовленной папки ServerSetup. Укажи отдельные пустые папки и новую базу.
Для SQL установщик создаёт базу с указанным именем. Существующая база не перезаписывается.
Пароль администратора приложения — 9–256 символов. Служебная Windows-учётка создаётся автоматически со случайным паролем; пароль твоей Windows-учётки не нужен.
После установки выдай пользователям права и заново настрой интеграции. Автоматического переноса старых данных в этом выпуске нет.
