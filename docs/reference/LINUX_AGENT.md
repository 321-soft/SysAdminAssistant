# Агент мониторинга Linux

Обновление существующего агента без переустановки: [LINUX_UPDATE_0.32.md](LINUX_UPDATE_0.32.md). В 0.32 добавлены отдельные пороги /boot/EFI, inode и корректный контроль oneshot/таймеров.

Агент предназначен для Debian и Ubuntu x64 с systemd. Он собирает показатели, которые читает служба мониторинга; на сервере нужен SysAdmin Assistant той же версии. Доступ на вход к Linux-агенту не требуется.

1. Обнови сервер и клиент Assistant этой версии.
2. В «Устройствах» создай или открой устройство, перейди на вкладку «Агент» и нажми «Установить Linux». Одноразовая команда копируется в буфер; она действует 15 минут.
3. Подключись к Debian/Ubuntu по SSH и вставь команду целиком. Для установки необходим root или sudo. Если curl отсутствует, сценарий попробует установить его через apt.
4. После регистрации в карточке Assistant сверь отпечаток ключа с тем, что выводит `sudo cat /var/lib/sysadminassistant-agent/status.json`, и нажми «Подтвердить». Только после этого сервер принимает отчёты.
5. В карточке настрой «Пороги», «Пороги сети» и «Роли и службы». Можно добавлять отдельные службы и исключать ненужные.

Агент передаёт загрузку CPU и RAM, swap, место на доступных файловых системах, uptime, скорости сетевых интерфейсов, состояние выбранных служб и сведения из локального кэша APT. Он не запускает поиск, установку обновлений, команды администрирования и изменения служб по запросу сервера. Исполняемый файл агента включён в пакет сервера; SDK и .NET на целевом Linux-сервере не нужны.

В «Журналах» настраиваются события Linux: ошибки памяти и диска, ядра, аварийные остановки служб и серия неудачных SSH-входов. Сбор начинается с момента первого подключения. Для доступа к системному журналу установщик добавляет учётную запись saa-agent в группу systemd-journal. Она получает право читать системные журналы; агент передаёт только выбранные им категории. Если журнал недоступен, в состоянии отображается предупреждение.

Агент проверяет подпись обновления сервера и применяет его через отдельный systemd-таймер; при неудачном старте предусмотрен откат. Сертификаты агента продлеваются автоматически через сервер. Сервер и агент должны оставаться доступны друг другу по HTTPS.

Проверка состояния на Linux:

```bash
sudo systemctl status sysadminassistant-agent.service
sudo journalctl -u sysadminassistant-agent.service -n 100 --no-pager
sudo cat /var/lib/sysadminassistant-agent/status.json
```

Сначала проверь установку и обновление на тестовой виртуальной машине: проверка публикации на Windows и установка на реальном Debian/Ubuntu с systemd зависят от окружения.
