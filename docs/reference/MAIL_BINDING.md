
- В форме «Привязать» доступны условия темы и тела. Можно заполнить только тему, только тело или оба поля.
- До 32 буквальных условий в каждом поле, собственный выбор И/ИЛИ; отдельный выбор «тема И тело» / «тема ИЛИ тело».
- Можно выделить постоянную часть темы и добавить в условия. Регистр не учитывается, * и ; — буквальный текст.
- Предпросмотр, применение к старым/будущим письмам, защита существующих связей и конфликты сохранены. Изменение темы делает старый предпросмотр недействительным.
- Условие только темы работает и при отсутствии сохранённого тела; это позволяет привязать запись, но не восстанавливает отсутствующий текст для анализа результата.

## Расписание
- В форме задания настройка «Допуск ± N минут». Например, 21:00 ±120 — с 19:00 до 23:00 включительно.
- Допуск может пересекать полночь; ранний отчёт до полуночи засчитывается ожидаемому запуску после полуночи.
- Пересекающиеся окна соседних запусков отклоняются. Общая граница засчитывается только одному запуску.
- Старые задания/архивы сохраняют прежнее правило раннего завершения; открой задание и сохрани допуск, чтобы включить симметричное окно. Это предотвращает неожиданную смену статусов старых настроек при обновлении.
- Лампа последнего результата и контроль расписания остаются отдельными: поздний/ранний отчёт может быть успешным по содержимому и одновременно не попадать в окно расписания.

# 0.10.0 — разбор писем и открытые проблемы устройств

- В задании и таблице резервного копирования добавлена «Система бэкапа». Можно выбрать систему из словарей или автоопределение.
- В устройстве добавлен «Словарь писем устройства». При автоопределении и отсутствии признаков в письме тип QNAP NAS использует QNAP, Synology NAS — DSM. Явная система задания имеет приоритет над словарём устройства.
- Привязка письма повторно анализирует сохранённый текст по текущему словарю: результат, критичность, доказательства и рекомендации. Такой же анализ выполняется для следующих писем по правилу.
- «Разобрать письма» в устройствах и заданиях повторно обрабатывает уже привязанные письма. При изменении выбранной системы у существующего объекта клиент запускает повторный разбор, если есть право изменять отчёты. Для ручного повторного разбора нужны права изменения соответствующего раздела и отчётов.
- В резервном копировании отображаются только созданные задания. Обычные письма устройства, в том числе QNAP HBS и Veeam, не создают задание автоматически.
- Цвет устройств в реестре и на главной учитывает все открытые критические события и предупреждения любого источника. Устройства с проблемами стоят выше.
- Карточка устройства открывает вкладку «Проблемы», если есть события. Видны количество, дата, источник, причина и основание анализа. Двойной щелчок / «Открыть письмо» открывает исходное письмо.
- «Решено» закрывает ровно одно выбранное событие; нужны право изменения отчётов и доступ к устройству. Пока есть хотя бы одно критическое событие, цвет красный. Только предупреждения — жёлтый. Когда событий нет, цвет определяется доступностью и сервисами: исправное устройство зелёное, недоступное остаётся красным. Архив и режим обслуживания сохраняют свой специальный статус.
- Обычное последующее информационное письмо не снимает старую тревогу. Повторный анализ не открывает закрытые события и не дублирует их. Новое критическое письмо создаёт новую проблему.
- Критичность устройства и результат бэкапа различаются. Системное уведомление QNAP может быть «Событие / Критично», без выдуманного результата резервного копирования.
- Нераспознанный результат показан явно. Совпадение фраз привязки не означает успеха. Если исходный текст старого письма недоступен, повторный анализ не восстановит его из ничего.
- Добавление столбцов сохраняет существующие данные SQLite и SQL Server; экспорт/импорт переносит выбранные словари. Сервер и клиенты необходимо обновить вместе.

## После обновления
1. Собери комплект через PUBLISH.bat и обнови сервер через ServerSetup/SETUP_SERVER.cmd. Обнови Client.
2. В существующем устройстве/задании выбери нужный словарь. Для ранее привязанных писем нажми «Разобрать письма».
3. Открой карточку проблемного устройства, проверь письма и отмечай устранённые события кнопкой «Решено».

Выпуск исходников: PUBLISH.bat выполняет сборку и проверки на Windows перед публикацией. GUI, реальный IMAP, SQL Server и запуск Windows-службы здесь не проверялись.


# Привязка писем и повторные запуски

## Быстро привязать одно письмо
В Отчётах выбери письмо и нажми «Привязать», либо нажми правой кнопкой по строке → Привязать.
Эта же кнопка есть в открытом письме. Для DMARC привязка к устройству/бэкапу не применяется.
Выбери устройство или задание. Если автоматическое правило не отмечено, изменится только выбранное письмо.
У нераспознанного результата цель сохранится, но письмо останется в очереди до разбора результата — программа не придумывает успешный бэкап.

## Правило по нескольким строкам
1. В окне привязки, вкладка «Письмо и строки», выдели постоянную строку текста и нажми «Добавить выделенное в условия».
2. Повтори для других строк. Можно также вписать условия вручную: одно на строку, до 32.
3. Выбери «Все строки (И)» либо «Хотя бы одна строка (ИЛИ)».
4. На вкладке «Цель и применение» отметь автоматическую привязку следующих писем.
5. При необходимости отметь применение к старым письмам.
6. Нажми «Показать совпадения», проверь количество и первые 30 примеров.
7. Подтверди кнопкой «Привязать».

Пример И:
Host: NAS-A
Task GUID: tenant-A
Подойдут письма, содержащие обе строки. Host: NAS-B с таким же отправителем и темой не подойдёт.
Пример ИЛИ:
Task GUID: current-name
Task GUID: legacy-name
Подойдёт одна из альтернатив для выбранного задания.

Регистр не важен; пустые строки и повторяющиеся условия игнорируются. Это буквальное вхождение текста. Символы * и ; не являются специальными разделителями или регулярными выражениями.
Новое правило из письма проверяет только строки тела; скрытых ограничений по теме, отправителю и источнику нет. DMARC обрабатывается отдельно.
В старом редакторе правил можно отдельно сочетать тему, отправителя и группу строк тела.

Чужие существующие привязки по умолчанию не меняются. Для их замены есть отдельная галочка; после её изменения нужно повторить просмотр.
Если другое активное правило совпадает с теми же письмами и задаёт другую цель или другой принудительный результат, будут показаны номера конфликтующих правил. Автоматическое правило не сохранится до устранения конфликта. Привязка только одного письма остаётся доступна.
Если письма/правила поменялись после просмотра, сохранение просит обновить просмотр и не делает частичных изменений.
У старых распознанных писем может не быть исходного текста; такие записи пропускаются и считаются отдельно. Сверка с IMAP и открытие сохранившегося письма позволяют дочитать его текст.

## Один бэкап дважды в день
Задания бэкапов → Изменить → ожидаемые завершения:
09:00; 21:00
До 24 времён в сутки. Дни недели и допуск общие для задания; допуск должен быть меньше интервала между запусками.
На главной и в заданиях показаны отдельные строки для каждого времени.
Правило по строкам определяет задание, а время выполнения внутри отчёта — запуск. При отсутствии времени отчёта используется поступление IMAP, затем заголовок, если IMAP-дата неизвестна; источник времени отмечается в разборе.
Утренний отчёт не закрывает вечернее ожидание. На границе допуска один отчёт засчитывается только одному автоматическому окну.
При ручной привязке можно явно выбрать запуск для выбранного письма. Для массово привязываемых прошлых и будущих писем запуск определяется автоматически.
Время, назначенное вручную, не закрывает другой запуск. Изменение расписания начинает новую точку контроля, как и в прежней версии.

## Установка
Запусти PUBLISH.bat, затем SETUP_SERVER.cmd на сервере. Установщик сам обновляет существующую 0.6.x.
Обнови и клиент: старые клиенты не знают о новых временах/условиях, поэтому их следует закрыть на время обновления и далее использовать новый комплект Client.
Данные не удаляются: добавляются несколько столбцов с безопасными значениями по умолчанию. Прежние задания с одним временем и прежние одиночные условия продолжают работать.
Нужны права изменения Отчётов и просмотра раздела выбранной цели (Устройства или Задания). Расписание редактируется с правом изменения Заданий.
