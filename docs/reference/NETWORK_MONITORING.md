# Сеть, правила и Telegram · 0.10.0

## Общий редактор
В разделе «Коммутаторы / сеть» выбери MikroTik и нажми «Правила». Таблица одинакова для любых площадок: одна строка — одно правило. В интерфейсе нет специальных полей для Москвы/Петербурга. «Добавить», «Изменить», «Копировать», «Удалить», включение и настройки Telegram доступны пользователям с правом изменения раздела сети.

В правиле выбираются:
- тип: состояние интерфейса или сообщение в логе;
- важность и включение;
- для интерфейса: точные имена, фразы комментариев, задержка, число успешных опросов;
- для лога: буквальные фразы И/ИЛИ, темы RouterOS (любая), исключения (любое), порог и окно, группировка по IP из `from …` или по всем источникам;
- предшествующие фразы/число совпадений для корреляции (например, успешный вход после отказов);
- группа повышения важности: одинаковый ID объединяет связанные правила в одну проблему с повышением важности;
- закрытие после заданного периода без повторов или вручную, отправка в Telegram и сообщение о закрытии.

Имена интерфейсов переносятся из ранее выбранного словаря и старых назначений. Свои сохранённые наборы не перезаписываются будущим импортом профиля. Чтобы применить обновлённый профиль заново, явно выбери замену набора в редакторе. Сохранение пустого набора выключает пользовательские правила; контроль доступа к API и чтения логов остаётся системной проверкой.

## Стандартные правила
| Событие | Уровень / порог | Закрытие |
|---|---|---|
| Неверный пароль | Информация: 1 попытка | Тишина 3600 с |
| Повторные неверные пароли | Предупреждение: 5 за 300 с с одного IP | Тишина 3600 с |
| Возможный перебор пароля | Критично: 20 за 300 с с одного IP | Тишина 3600 с |
| Успешный вход после отказов | Критично: после 5 отказов за 600 с с того же IP | Вручную |
| Вход в управление | Информация | Тишина 60 с |
| Изменена конфигурация | Предупреждение | Вручную |
| Любая обнаруженная перезагрузка | Критично | Вручную |
| Ошибки памяти, ядра, накопителя | Критично | Вручную |
| Проблемы питания, вентилятора, температуры | Критично | Вручную |
| Недостаток места на накопителе | Предупреждение | Вручную |
| Ошибки сертификата / SSL | Предупреждение: 3 за 300 с | Тишина 900 с |
| Сообщение о SYN flood / сканировании | Предупреждение | Тишина 900 с |
| Другие сообщения с темой critical | Критично, с исключениями для отдельных правил | Вручную |

Это редактируемые шаблоны буквальных сообщений. Наличие события и формулировка зависят от RouterOS и настроек его logging; это не полный словарь всех ошибок производителя. Записи должны быть доступны в `/log` через API. Программа только читает RouterOS и не включает логирование/правила firewall на устройстве. Обычное отключение VPN-пользователя само по себе не становится критическим.

Перезагрузка дополнительно определяется по уменьшению uptime между успешными опросами. Это не устанавливает её причину. Если соответствующая информация не попала ни в доступные логи, ни в наблюдаемое уменьшение uptime, приложение не может доказать перезагрузку.

Первый буфер логов при подключении/переходе на новую обработку отмечается как история. Он не создаёт массовые старые тревоги и не участвует в счётчиках. Последующие новые записи дедуплицируются. Окно повторов использует время обнаружения на сервере; исходное время RouterOS показывается отдельно. Хранятся последние 1000 уникальных записей и до 2000 закрытых проблем плюс активные.

## Закрытие и доставка
«События → Активные проблемы → Решено» закрывает выбранную проблему лога и сбрасывает её счётчик. Другие проблемы остаются. Интерфейсы закрываются только после подтверждённого восстановления. При ошибке API или чтения логов прежние проблемы не считаются восстановленными.

Все подключения Telegram используют общие настройки уровней. Закрытие сетевой проблемы относится к исходному уровню проблемы. Уведомления ставятся в постоянную очередь один раз на переход/повышение важности, повторяются после ошибки доставки и сохраняются при перезапуске. Полный текст логов и пароли в сообщения не отправляются. Получателями Telegram управляет администратор; все включённые уведомления идут в заданный общий чат.

Сетевые события, ICMP, сервисы, DNS/интернет, ошибки IMAP, отсутствие/нераспознанность отчётов и счета подключены к общей доставке. Результаты полученных писем отправляются существующим механизмом событий отчётов. Напоминания о счетах не доставляются в выходные; очередь сетевых тревог не блокируется отложенными счетами.

Состояние и защищённые подключения — `network-state.json`, профили — `network-dictionaries.json` в каталоге данных сервера. GUI-обновление копирует весь каталог. Пароли соединений защищены DPAPI и связаны с машиной. Копия только SQL/SQLite не включает эти JSON-файлы.

Формат журнала и темы: https://help.mikrotik.com/docs/spaces/ROS/pages/328094/Log
