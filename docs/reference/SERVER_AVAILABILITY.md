# Настройка через мастер (0.24.0)

В клиенте: Настройки → Внешний контроль сервера → Создать ZIP для хостинга. Выбрать Beget / shared-хостинг / собственный Linux-сервер. Указать приватный каталог, публичный document root, полный путь PHP CLI, URL и ID. Просмотр показывает точные пути и cron до сохранения. После «Сохранить как» готовый конфиг содержит текущего Telegram-бота и автоматически созданный либо сохранённый общий ключ.

Экспорт только для главного администратора: ZIP содержит секреты. Загружать на сайт только по START-HERE.txt; приватный config.php и состояние остаются вне публичной папки. Отдельная папка состояния не нужна. Выполнить init/test, поставить cron, затем включить сигналы из итогового окна. Сам экспорт настройки не меняет. Если окно закрыто, параметры можно перенести из config.php позже.

Для Beget предложен `/usr/local/bin/php8.4`, но путь надо сверить с панелью. Не использовать вслепую `php`: старая версия CLI может завершаться с кодом 255. Версия сайта и CLI — PHP 8.1+ 64-bit, curl. Подробная ручная настройка: WebWatchdog/README.md.

# Контроль сервера через свой сайт

Сервер Assistant раз в минуту посылает подписанный HTTPS-сигнал PHP-приёмнику на твоём сайте. Cron на хостинге каждые 5 минут проверяет время последнего сигнала. После 5 минут без сигналов отправляется одна красная тревога; после восстановления — одна зелёная. Фактическое обнаружение занимает примерно 5–10 минут после последнего сигнала из-за шага cron. Задержки самого cron и Telegram могут увеличить срок.

Полная пошаговая установка: WebWatchdog/README.md. Пакет также копируется в Client/WebWatchdog и ServerSetup/WebWatchdog при PUBLISH.bat.

Наблюдатель должен находиться вне ДЦ мониторинга, иметь собственный работающий cron и исходящий доступ к Telegram. Если упадёт сам сайт/хостинг или его интернет, он тоже не сможет отправить сообщение. Не требуется VPN или публикация API Assistant наружу: запросы идут на сайт через обычный интернет.

Сигнал подтверждает запуск службы, чтение БД и исходящий путь до сайта; он не проверяет API из каждой клиентской сети. Пропажа сигналов — потеря связи/наблюдаемости, а не доказанный отказ всего ДЦ. При плановом обслуживании ставь maintenance=true на сайте и обратно false по окончании.

После обновления внешнюю проверку нужно настроить заново: HTTPS URL твоего PHP-файла, server_id и общий ключ. Старые параметры стороннего наблюдателя не используются, функция без нового адреса и ключа остаётся выключенной. Не отключай прежний реальный контроль до успешного теста новой схемы.
