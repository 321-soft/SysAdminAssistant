# Доверенные сети и показатели устройства · 0.33

## Изменение сетей

Главный администратор: Настройки → Сервер → Доверенные сети. Одна частная подсеть CIDR на строку, например 192.168.20.0/24. Сохранение сразу меняет доступ на уровне приложения; переустановка не нужна. Loopback остаётся разрешённым для локальной диагностики. Список защищает и клиентов, и входящие соединения агентов.

Windows Firewall — второй независимый уровень. Если у службы нет прав администратора (нормально для выделенной учётной записи), после сохранения появится соответствующее сообщение и готовая команда PowerShell. Выполни её **на сервере от администратора**. Без этого новая подсеть может оставаться заблокированной Windows Firewall. Не отключай firewall целиком. Если штатное правило отсутствует или управляется доменной политикой, требуется проверить его на сервере; программа не создаёт разрешение на весь трафик.

Если исключаешь адрес текущего клиента, приложение отдельно запросит подтверждение. Сначала добавляй новую сеть и проверяй подключение оттуда, только потом удаляй старую. Два администратора не могут незаметно перезаписать изменения друг друга.

Рабочий список: каталог данных сервера/trusted-networks.json. Предыдущий: trusted-networks.json.previous. При ошибочном подтверждённом отключении доступ можно восстановить локально на сервере: остановить службу SysAdminAssistantServer, вернуть предыдущий файл под именем trusted-networks.json, запустить службу; затем проверить адреса штатного правила Windows Firewall. Это не требует удаления БД. Добавь оба файла в обычную резервную копию каталога данных. При отсутствии override используется исходный список server.json. Повреждённый override не игнорируется в пользу более широких разрешений.

«Разрешённые подсети назначения» в установщике агента — **другая настройка**: куда самому агенту разрешено подключаться. Изменение доверенных сетей сервера не расширяет эти ограничения автоматически и не меняет сертификаты, регистрацию, маршруты или firewall на других устройствах.

## Полоски показателей

Устройства → карточка → Агент. CPU, RAM, Windows-диски с буквами или Linux-точки /, /boot и другие, swap (если существует), сетевые интерфейсы. Полоска диска показывает занятое пространство; доступный остаток подписан отдельно. На Linux зарезервированные блоки ФС отдельно объясняются в подробностях, поэтому «занято + доступно» не всегда равно полному размеру. Порог диска проверяет остаток, не цветовую границу, нарисованную на глаз.

Подробности и пороги открывают факты и рекомендации. Изменение условий — кнопки «Пороги», «Тома и пороги», «Пороги сети» в той же карточке. Цвет реагирует на настроенные условия. Отключённый контроль не является подтверждением отсутствия проблем; его состояние указано в подробностях.

Панель опрашивается каждые 10 секунд; сам агент передаёт с заданной периодичностью. Серым помечаются данные старше max(90 секунд, три интервала передачи), отсутствующая связь или отозванный доступ. CPU-график хранит до 60 новых измерений только пока карточка открыта, повтор одного отчёта не добавляет точку.

Для сети: приём/передача в байтах в секунду, скорость канала в битах в секунду. Процент — более загруженное из двух направлений, а не их сумма. Если скорость неизвестна, процент не выдумывается; реальную пропускную способность можно задать в «Пороги сети». Первый сетевой замер нового Windows-агента нужен для получения базы счётчиков, скорость появляется со следующего отчёта. Для виртуальных NIC скорость драйвера может отличаться от реального WAN — используй ручную настройку.

Новая панель требует обновления сервера и клиента. Для сетевых показателей Windows нужен агент 0.33; дождись его подписанного автообновления. Старые агенты не получают команд управления и сохраняют прежнюю регистрацию. Не переустанавливай их ради оформления интерфейса.

## Пароли сервисов

В «Пароли» открой запись на изменение и выбери «Связать с сервисом». Можно оставить одновременно связь с устройством. В таблице появилась колонка «Сервис» и переход к его данным. Во вкладке «Сервисы» выбери строку и нажми «Пароли сервиса»: если доступных записей несколько, появится выбор, затем обычное окно секрета с подтверждением доступа.

Права на сервис не дают права на чужой пароль. Требуется разрешение «Пароли», собственная доступная запись и стандартная разблокировка. Назначение новой связи также требует доступа к «Сервисам». Переименованный сервис сохраняет связь по ID. Перед удалением сервиса нужно снять привязку; пароль автоматически не удаляется.

В Excel добавлена колонка «Сервис ID». Для нового шаблона пустая ячейка снимает связь. Старый семиколоночный шаблон остаётся допустимым и при обновлении существующей записи сохраняет её прежний ServiceId. Перенос БД переназначает ID сервиса вместе со связью. Обновление добавляет nullable-столбец в существующую таблицу паролей (SQLite/SQL Server), шифрование секретов и старые поля не меняет. Перед обновлением сделай обычную резервную копию БД; чистая установка не нужна.

## Проверка

Полная сборка и тесты доступны через VERIFY.cmd/PUBLISH.bat. Результаты этой версии — verification/AUDIT_0.33.md. Windows GUI и изменение настоящего Windows Firewall в Linux-среде не запускались; это ограничение проверки, а не подтверждение работоспособности любой доменной политики.
