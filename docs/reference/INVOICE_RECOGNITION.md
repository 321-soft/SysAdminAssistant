# Счета из почты · 0.30.1

## Где находится

Настройки → **Распознавание счетов**: почта, проверка подключения, поставщики/обучение, повторная проверка ожидающих, история. Счета → **Счета из почты · проверить**: очередь и архив документов. Рядом сохранены прежние кнопки ручного добавления, изменения, оплаты и истории. Повторяющиеся платежи не заменяются почтовыми.

В каждой строке платежа с документами есть **PDF ↓**. В карточке платежа — «Счёт · реквизиты и документ» и скачивание. При нескольких документах/периодах предлагается выбор. PDF сохраняется без изменения исходных байтов через «Сохранить как». PNG/JPEG можно скачать оригиналом либо преобразовать в PDF с суффиксом converted. Файл не открывается автоматически. Исходный PDF хранится в БД сервера и доступен после удаления письма из IMAP. Письма без вложений имеют только текстовый просмотр, исходного PDF у них нет.

## Настройка с нуля

1. Соберите PUBLISH.bat, обновите сервер и клиент. Добавляются две таблицы архива InvoiceRecord / InvoiceAttachment; старые платежи и настройки не меняются. Для существующей SQL-базы нужны права на создание новых таблиц. Прежняя схема 7 сохраняется. Агентов ради счетов обновлять не нужно.
2. В настройках откройте «Почта для счетов». Лучше выделить папку или отдельный ящик: обработка отчётов и DMARC использует прежние настройки и независимый обработчик. Введите IMAP-адрес, TLS-порт, логин, пароль приложения, папку. Пароль хранится штатной защитой Windows на сервере, при следующем открытии не выдаётся клиенту.
3. Нажмите «Проверить подключение». Проверяются TLS, вход и чтение выбранной папки. Не требуется отдельно устанавливать Excel или SDK на сервере для распознавания.
4. По умолчанию загружаются только новые письма **после начальной проверки**. После сохранения включённых настроек начальная проверка запрашивается сразу; дождитесь в истории «Начальная отметка сохранена». Для старых документов выключите «Только новые» и задайте дату. При смене ящика/папки/начала загрузки создаётся новая отметка; для OnlyNew это новая начальная точка. После перерыва работа продолжается с сохранённого UID. Письма открываются в ReadOnly, флаг прочитанности не меняется.
5. Укажите точные адреса разрешённых отправителей. Для автоматического добавления включите проверку SPF/DKIM и настройте принимающую систему. Для Яндекса есть профиль; для другой почты укажите точные auth-id. Подтвердите очистку поддельных Authentication-Results только если ваш почтовый сервер действительно её выполняет. Один From без проверки подлинности не разрешает автоматическое создание платежа.
6. Первые документы появятся в очереди проверки. Откройте счёт: слева **текстовый предпросмотр**, справа поля. Проверьте поставщика, номер, сумму/валюту, дату счёта, срок и реквизиты. Срок не подменяется датой получения. Оригинал PDF скачивается отдельно; встроенного графического PDF-просмотрщика в этой версии нет. «Показать исходное письмо» выводит безопасный текст без внешних картинок.
7. Подтверждая карточку, выберите разовый платёж либо существующий платёж и его период. Это не меняет расписание и не отмечает оплату. При совпадении с регулярным платежом автоматическое создание останавливается до выбора пользователя. Для надёжного сопоставления укажите связанный регулярный платёж в шаблоне; поиск похожего названия — лишь подсказка.

## Обучение поставщику

Всё находится в Настройки → Распознавание счетов → Поставщики и обучение.

Добавьте шаблон: точный отправитель, при необходимости фраза в теме, подтверждённые название/ИНН/банк/счёт/валюта. Затем задайте подписи перед нужными значениями. Пример для суммы: `Всего к оплате`. Значение берётся справа от подписи или со следующей строки. При нескольких разных совпадениях поле считается неоднозначным. Если справа есть другое поле, используйте границу: `Всего: => НДС`. Это буквальные подписи, не программные скрипты.

Выберите сохранённый пример, откройте его текст и «Проверить правила на примере». Проверка не создаёт платёж. Подписи дополняют общие русские/английские правила. Шаблон не заполняет отсутствующую валюту или новые банковские реквизиты ожидаемыми значениями. Для отсутствующего срока можно задать число календарных/рабочих дней от даты счёта; карточка отмечает рассчитанный срок. Рабочие дни берутся из календаря компании.

Включите автоматическое создание только после проверки примера. При единственном подходящем шаблоне, подтверждённом отправителе, однозначных обязательных полях, достаточной оценке OCR и прошедших проверках создаётся отдельный неоплаченный разовый платёж. Изменившиеся реквизиты, несколько подходящих шаблонов, недостающие поля, пометка оплаты/корректировки или пересечение с регулярным платежом остаются на проверке. Для иностранной валюты требуется её явное присутствие в документе и совпадение с шаблоном; автоматической конвертации в рубли нет. Рублёвое числовое поле прежних платежей не используется для AED/USD/EUR и т. п.

«Применить правила к ожидающим» перепроверяет до 50 ожидающих документов за один запуск. Уже созданные платежи не переписываются. Если после уточнения полей обнаружится существующий счёт, новый платёж не создаётся: запись помечается дубликатом. Первоначально неподтверждённый отправитель не получает доверия задним числом от изменения шаблона — такой счёт подтверждается вручную.

## Дубли и архив

Проверяются ключ IMAP, хеш файла и поставщик/номер/дата/сумма/валюта. Повтор/пересылка не создают новый платёж. Разные файлы одной подтверждённой копии сохраняются как альтернативные оригиналы. При тех же номере, дате и сумме, но других банковских реквизитах документ сохраняется отдельно и требует проверки. Исправление суммы при том же номере также требует проверки. Статус «Пропустить» сохраняется, повтор того же файла его не возвращает.

Очередь показывает до 2000 последних записей с приоритетом ожидающих; старые документы платежа запрашиваются отдельно по PaymentId, поэтому скачивание из строки не зависит от этого ограничения. История обработки ограничена последними 1000 сообщениями. Документы не удаляются настройкой хранения отчётов бэкапа. Удаление платежа не удаляет исходный счёт из архива.

## Форматы, ограничения и установка OCR

Текстовые PDF читаются PdfPig. Для PNG/JPEG и сканов используется локальный Tesseract с русской и английской моделями. Нет LLM, внешнего сервиса распознавания или отправки документов в облако. OCR сам использует обученные модели; «обучение поставщику» в интерфейсе означает сохранение правил извлечения полей.

Модели включены в исходную сборку и копируются на сервер; каждый раз скачивать их не надо. Нативный OCR только для Windows x64; нужны библиотеки Microsoft Visual C++ 2019 или новее. PUBLISH предлагает включить официальный VC++-установщик, кэширует его в RuntimePackages и проверяет подпись Microsoft. При новой установке/обновлении серверный GUI-установщик устанавливает его при необходимости. Выбор .NET Runtime независим. Если отказаться от VC++ и его ещё нет на сервере, текстовые PDF продолжат работать, а сканы останутся на проверке с ошибкой OCR. Возможна штатная необходимость перезагрузки Windows после установки VC++.

До 8 МБ на файл, до 16 МБ на письмо, до 8 файлов на письмо, до 10 страниц PDF; до 100000 символов текста. Больше и неподдержанные вложения отмечаются в истории. Читаются PDF/PNG/JPEG по сигнатуре содержимого, ZIP/Office/макросы не запускаются и не распаковываются. Парольные, составные или необычно закодированные PDF могут потребовать ручной проверки. Для сканов PDF извлекаются встроенные изображения; это не универсальный рендерер всех PDF-конструкций и фильтров. При ошибке чтения принятого PDF оригинал сохраняется в очереди.

Извлечение выполняется отдельным процессом, последовательно, с таймаутом 60 секунд. На Windows применён Job Object с лимитом памяти 512 МБ, запретом дочерних процессов и завершением при закрытии родителя. Это ограничение ресурсов, **не полноценная песочница безопасности**. Не следует считать вложения доверенными только потому, что программа извлекла из них текст. Скачать оригинал вправе пользователи с чтением раздела Счета, подтверждать — с изменением. Настройки требуют прав изменения настроек, работа с обучающими документами дополнительно требует доступа к счетам.

## Значок Windows Update

Сервер учитывает положительный PendingCount, восстанавливает отсутствующую проекцию из последнего отчёта агента, а клиент раз в 20 секунд точечно обновляет значок на главной и в устройствах, не перестраивая страницу или открытую форму. Ошибка проверки не стирает последнее известное наличие обновлений; подтверждённое Current без ожидающих обновлений и без необходимости перезагрузки скрывает значок. Цвет устройства и уведомления Telegram из-за обновлений не меняются. Требуются сервер и клиент 0.30.1; если агент уже присылает результаты Windows Update, переустановка агента не нужна.

Проверки и ограничения среды — verification/AUDIT.md. Полноценный Windows OCR/GUI/IMAP и SQL Server в среде разработки не запускались; перед включением автообработки проверьте пример вашего поставщика.
