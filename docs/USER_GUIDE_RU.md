# SysAdmin Assistant

## Обзор

Мониторинг выполняется серверной службой независимо от открытого клиента. Главная страница показывает устройства, резервное копирование, коммутаторы и счета. Проблемные устройства поднимаются выше исправных. Серый цвет означает отсутствие подтверждённых данных; это не успешная проверка.

Красный — активная критичная проблема, жёлтый — предупреждение, зелёный — подтверждённое исправное состояние. Значок обновлений отделён от состояния устройства. Откройте строку, чтобы посмотреть причину, время проверки и историю. Открытие клиента и обновление списка не заменяют серверный мониторинг.

F5 перечитывает текущий список. При появлении новых данных открытая форма не должна пересоздаваться: используйте «Обновить», когда закончите редактирование. Ctrl+K открывает общий поиск. F1 открывает справку.

Внизу окна откройте «Настроить рабочий стол». Размеры 2×4 и 4×2 означают ширину и высоту в ячейках. На узком экране ширина карточки ограничивается доступным числом колонок. Включите «100% ширины ряда», чтобы занять свободное место справа. «100% высоты» растягивает ряды до края области карточек; если карточки не помещаются, остаётся прокрутка. Настройка сохраняется отдельно для каждого раздела и пользователя.

## Подключение и сеансы

Введите HTTPS-адрес сервера, имя пользователя и пароль. Отпечаток SHA-256 берётся из установщика или информации сервера. Сверяйте его по независимому доверенному каналу: доступность TCP-порта сама по себе не подтверждает подлинность сервера.

«Запомнить вход до закрытия приложения» сохраняет обычный сеанс на время работы клиента. Длительный разрыв связи и отзыв прав требуют повторного входа. Доступ к персональным данным и секретам подтверждается отдельно. Закрытие окна в область уведомлений не завершает клиент; используйте «Выход».

Если подключение не удалось, проверьте службу сервера, маршрут, порт HTTPS, доверенные сети и отпечаток. Не отключайте проверку сертификата для устранения ошибки TLS. Изменение доверенных сетей доступно главному администратору в настройках сервера.

## Устройства и подключения

В разделе «Устройства» хранится запись оборудования, адрес доступности, площадка, агент и связи с заданиями. Добавление устройства не создаёт задание резервного копирования: его расписание задаётся отдельно. Сетевое оборудование RouterOS настраивается в разделе «Коммутаторы».

В карточке задаются цели LAN/WAN, параметры агента, пороги и быстрые подключения Web, SSH и RDP. Web открывается браузером по умолчанию, RDP — клиентом Windows, SSH — установленным обработчиком протокола. Assistant не исполняет команды через мониторинговый агент.

Полосы дисков и памяти относятся к последнему отчёту агента. Для Linux отображается точка монтирования, для Windows — том. Смотрите время данных, проценты, абсолютный остаток и пороги. Обновления ОС показываются отдельным значком и не должны сами делать устройство аварийным.

## Сервисы и доступность

Сервисы проверяются сервером по настроенному протоколу и адресу. Это проверки HTTP/TCP, а не список systemd или служб Windows: системные службы настраиваются в политике агента устройства.

Для доступности можно указать несколько целей LAN и WAN. Задержка уведомления по умолчанию — две минуты: кратковременный сбой, восстановившийся до истечения задержки, не должен создавать уведомление о недоступности. Это правило не заменяет расписание резервного копирования.

Пароль можно связать одновременно с устройством и сервисом без создания дубликата. Связь не предоставляет дополнительных прав на секрет. Не помещайте пароль или токен в URL HTTP-проверки.

## Резервное копирование

Создайте задание, выберите устройство, систему резервного копирования и ожидаемые времена завершения. Допуск ±N минут учитывает раннее и позднее завершение. Текущий ожидаемый запуск оценивается отдельно: вчерашний успешный отчёт не подтверждает выполнение сегодняшнего.

Письмо сначала связывается с заданием, затем результат анализируется по словарю источника. «Отчёт получен» без распознанного результата не равен успеху. В словарях учитываются контекст и счётчики: Error 0 не должен означать ошибку только из-за слова Error.

При отсутствии отчёта проверьте диагностику IMAP, фактическую дату поступления, правила привязки и окно задания. «Проверить почту сейчас» запускает сбор на сервере. Разделяетcя проблема доставки писем и факт отсутствия подтверждения бэкапа; последнее не доказывает, что сами данные не скопированы.

## Почта, привязки и словари

Настройте IMAP-ящик в настройках и проверьте подключение. Сертификат TLS проверяется; для обычного чтения не меняется флаг прочтения. У счетов и отчётов отдельные настройки сбора: существующая интеграция не заменяется новой.

Откройте письмо, чтобы увидеть отправителя, дату поступления на IMAP, дату отправителя и тело. Внешние изображения и активное содержимое не запускаются. Через «Привязать» задайте условия темы, тела или обоих полей, несколько фраз и логику И/ИЛИ. Сначала проверьте совпадения; похожие письма могут относиться к разным заданиям.

Словарь результата применяется после привязки. Не меняйте уникальные признаки задания на общие слова «успех» или «ошибка». Уведомления об обновлениях можно привязать отдельно; после ручной установки версии подтвердите её в соответствующем уведомлении, если источник — только письмо.

## Коммутаторы и MikroTik

Добавьте MikroTik в разделе «Коммутаторы», задайте адрес API-SSL, порт, логин с правами read + api и доверие сертификату. При необходимости укажите SHA-256 сертификата маршрутизатора. Сертификат HTTPS Assistant и сертификат RouterOS — разные сертификаты.

Assistant выполняет мониторинг, чтение журналов и анализ конфигурации. Команды исправления показаны для ручного применения и не выполняются программой. Проверка учитывает путь пакета: вход, NAT, INPUT или FORWARD, порядок правил и ограничения, включая IPsec. Прочитайте доказательства и ограничения анализа перед изменением firewall.

Игнорирование относится к конкретной устойчивой проблеме и сохраняется после повторного опроса. Восстановление WAN/туннеля закрывает проблему по фактическому состоянию. Повторные неудачные входы продлевают период тишины от последней попытки; отсутствие новых записей не равно доказанному взлому.

## Агенты Windows и Linux

Агенты передают состояние системы и журналы. Они не принимают команды администрирования. Пакет создаётся из карточки устройства и содержит привязку к серверу; храните установочные пакеты приватно. Для Linux Debian/Ubuntu используйте сгенерированную команду установки, а не ручную сборку SDK.

Роли сервера помогают выбрать системные службы. Дополнительную службу можно добавить и удалить в настройках устройства. CPU, RAM, swap, сеть, диски и inode имеют отдельные пороги. Для /boot и /boot/efi применяются специальные настройки: небольшой исправный раздел не обязан иметь несколько гигабайт свободного места.

Состояние oneshot inactive/dead после успешного завершения допустимо. У таймера отдельно контролируются расписание и результат задания. SSH может обслуживаться через socket activation без постоянно работающего ssh.service. Для ошибки смотрите тип unit, код завершения, последнее выполнение и оригинальную запись.

Обновления агента подписаны и сохраняют регистрацию и ключ. Служба может быть запущена, но не передавать данные: проверяйте время последнего отчёта, журнал агента, маршрут и доверие серверу.

## Windows-агент: установка, обновление и повторная регистрация

ПАКЕТ ПРИВЯЗАН К КАРТОЧКЕ
Откройте «Устройства → нужное устройство → Агент → Создать установщик Windows». Пакет содержит разрешение на регистрацию в выбранной карточке. Имя компьютера заранее не сверяется: если впервые запустить пакет на другом компьютере, его агент может занять эту карточку. Для каждого компьютера создавайте свой установщик. Сверьте имя машины и отпечаток ключа перед подтверждением.

ИМЕНА ФАЙЛОВ
По умолчанию файлы называются DC01_v0.42.10_Setup.exe и DC01_v0.42.10_Update.exe. DC01 — название карточки, версия берётся из агента внутри пакета. Запрещённые символы заменяются на подчёркивания. Имя файла не меняет привязку.

ОБНОВЛЕНИЕ И ПОВТОРНАЯ УСТАНОВКА
«Пакет обновления Windows-агента» сохраняет существующий ключ и регистрацию. В нём нет разрешения на новую регистрацию. Если агент полностью удалён, откройте ту же карточку, отзовите прежний доступ, если агент ещё числится зарегистрированным, создайте новый Setup.exe, установите его и подтвердите новый ключ. Удалять саму карточку не нужно.

АГЕНТ 0.42.3 НЕ ОБНОВЛЯЕТСЯ
Если 0.42.3 пишет «Нет ожидаемой службы агента», выполните sc.exe query SysAdminAssistantAgent на наблюдаемом компьютере. Если служба существует, один раз запустите подписанный пакет обновления из карточки этого устройства от администратора. Старый обновлятор падает до связи с сервером, поэтому одно обновление сервера не поможет. Если sc.exe возвращает 1060, служба не найдена: сначала проверьте состояние установки, не удаляйте данные агента ради диагностики.

## Linux-агент: штатное обновление и диагностика

После обновления сервера Assistant подтверждённый Linux-агент скачивает подписанный выпуск после успешной связи с сервером. Таймер systemd применяет скачанный пакет. Файл .exe относится к Windows; для Linux в карточке есть «Обновление Linux-агента». Повторно регистрировать исправный агент не нужно.

Проверить таймер: systemctl status sysadminassistant-agent-update.timer --no-pager
Посмотреть журнал: sudo journalctl -u sysadminassistant-agent-update.service -n 30 --no-pager
Применить уже скачанный пакет: sudo systemctl start sysadminassistant-agent-update.service
Проверить установленную версию: /opt/sysadminassistant-agent/agent --preflight

Сообщение «Обновление не загружено» означает, что применять пока нечего. Запуск службы обновления сам пакет не скачивает. Проверьте свежесть отчёта агента и наличие Linux-выпуска в опубликованном комплекте сервера.

При публикации сервера включите .NET Runtime (или заранее поместите проверенный установщик в RuntimePackages). Планировщик автообновления Windows-агента получает .NET Desktop Runtime x64 с сервера Assistant, проверяет подпись манифеста, хеш файла и SHA-512 Microsoft. Runtime устанавливается до остановки агента и замены его файлов, без автоматической перезагрузки. Если установщик требует перезагрузку, замена агента отложится до планового перезапуска. При переходе со старого работающего обновлятора на 0.42.14 сначала установится совместимая версия агента, а .NET обновится при следующей проверке. Если старый обновлятор уже не запускается, нужен подписанный пакет обновления для этого устройства.

## Kaspersky Security Center: OpenAPI, учётная запись и журнал

Откройте «Kaspersky» в левом меню под администратором Assistant, отметьте «Активировать» и нажмите «Подключение к KSC…». Устройство в реестре создавать не нужно. Сервер Assistant обращается к серверу администрирования KSC напрямую по HTTPS. Укажите, например, https://ksc.example:13299 без /api/v1.0. Используйте фактический порт OpenAPI вашего KSC; 13299 — типовое значение. Установка агента Assistant на машины KSC для этого не нужна.

В KSC создайте отдельного внутреннего пользователя, например saa_reader. В свойствах самого Сервера администрирования, в разделе «Безопасность», проверьте эффективное разрешение «Базовая функциональность → Чтение». Если ваша версия отдельно показывает право подключения к Серверу администрирования, проверьте и его. Права записи, выполнения задач, изменения настроек или удаления событий для чтения не выдавайте. В Assistant отметьте «Внутренняя учётная запись KSC» и оставьте домен пустым.

Если Windows не доверяет сертификату OpenAPI, откройте «Сертификат OpenAPI» → «Копировать команду». Выполните команду в PowerShell от администратора на самом сервере KSC. Она читает локальный klserver.cer и печатает SHA-256 из 64 символов. Вставьте его в настройки Assistant и нажмите «Проверить подключение». Если KSC использует другой файл, укажите путь к сертификату, предъявляемому на порту OpenAPI. Отпечаток действует только для настроенного адреса и порта. Имя и срок действия проверяются. После перевыпуска сверьте новый отпечаток на KSC и примените его; для прежнего подключения позиция чтения и привязки сохраняются.

Нажмите «Проверить подключение». При успехе сохраните подключение: начнётся фоновый сбор новых событий. Чтобы приостановить его, снимите «Активировать»; новые настройки и позиция чтения сохранятся. Для создания проблем откройте «Kaspersky → Правила Kaspersky» и добавьте встроенные типовые правила либо импортируйте JSON. В разделе Kaspersky отдельно включаются уведомления Telegram, выбираются критичные события, предупреждения и восстановление. Используются бот и чат из общих настроек Telegram.

## Проблемы и история

Активная проблема отличается от сохранённого события журнала. Повторения одной причины объединяются по устройству, источнику и сигнатуре; сохраняются первое/последнее время и счётчик. Изменение причины или важности может создать отдельное событие.

Откройте проблему для фактов, порога, безопасных проверок, рекомендаций и условия закрытия. Автоматическое восстановление требует подтверждённого исправного состояния. Исторические записи остаются после восстановления. «Решено» отмечает разбор события, но не исправляет саму службу, сеть или диск.

Кнопки исходного письма относятся только к почтовым событиям. Не применяйте рекомендации удаления данных, форматирования или принудительной перезагрузки без собственного анализа и резервной копии.

## Счета, почта и распознавание

Ручные и повторяющиеся платежи работают независимо от распознавания счетов. До приближения срока платёж зелёный; по умолчанию за три рабочих дня — жёлтый; просроченный — красный. Рабочая неделя компании настраивается отдельно. История периодов позволяет отменить ошибочную отметку оплаты.

Распознавание из почты включается отдельно в настройках: ящик, допустимые отправители, подлинность писем, правила поставщика и обучение. Извлекаются номер, даты, сумма, валюта и реквизиты. Низкая уверенность, конфликт или неизвестный поставщик требуют проверки. OCR изображения может ошибаться; сверяйте сумму и банковские реквизиты с оригиналом.

Скачать PDF или оригинал можно из строки документа. Связь с повторяющимся платежом не означает оплату и не должна создавать второй платёж за тот же период. Подтверждайте поставщика и период перед автоматическим созданием.

## Пароли и связи

Хранилище защищает секреты и требует отдельного подтверждения доступа. Откройте карточку двойным щелчком: пароль скрыт, доступны «Показать пароль» и «Копировать пароль». Буфер очищается через установленный срок, если его содержимое не изменилось.

Одну запись можно связать с устройством и сервисом без дублирования секрета. Разрешение на просмотр связанного сервиса не предоставляет права читать чужое хранилище. Выдача прав по разделам выполняется главным администратором.

Экспорт в Excel может содержать открытые пароли: программа предупреждает об этом. Храните файл в защищённом месте и удалите после использования. Не отправляйте пароли в журналы, Telegram, обращения поддержки или снимки экрана.

## Инвентаризация и Excel

Карточки имущества хранят инвентарный номер, характеристики, стоимость, состояние и сотрудника. Выдача, возврат и списание оформляются актами. Проведённый акт хранит снимок реквизитов и характеристик на момент операции; последующее изменение карточки не переписывает документ.

Перед импортом скачайте шаблон Excel. Заполните лист данных по инструкции и проверьте предварительный просмотр. Обновление по ID предназначено для ранее выгруженных записей; не заменяйте ID вручную. Ошибочные ссылки на сотрудника или устройство должны исправляться до сохранения.

Доступ к сотрудникам и актам требует соответствующего права и подтверждения пароля. Увольнение сотрудника не удаляет историю; сначала оформите возврат имущества. Печатать в PDF можно через Microsoft Print to PDF.

## DMARC, SPF и DKIM

DMARC-отчёты помогают видеть источники отправки и результаты аутентификации домена. Импортируются XML и поддерживаемые архивы. Отчёт не является проверкой доступности почтового ящика и не доказывает подлинность каждого письма.

Для входящих уведомлений authserv-id относится к принимающей системе из Authentication-Results, а не к каждому отправителю. У Яндекса разные mxfront узлы; выбирайте профиль принимающей системы и контролируемые правила доверия, а не один случайный сервер из заголовка.

Доверять результатам можно, только если принимающая система удаляет поддельные заголовки со своими идентификаторами. Проверяются SPF/DKIM и выравнивание с From согласно выбранному режиму. Не добавляйте домен отправителя в доверенные authserv-id.

## Telegram и ежедневная сводка

Задайте токен бота, Chat ID, уровни важности и группы событий. Отдельные категории позволяют исключить ненужные сообщения. Выполните тест. Для закрепления списка проблем бот должен иметь право закреплять сообщения в группе.

Обычные сообщения обозначаются красным или оранжевым значком; восстановление — зелёным и по возможности ответом на исходную проблему. Закреп содержит текущие активные проблемы и обновляется сервером. Когда проблем нет, закреп снимается; сообщения и история не обязательно удаляются.

Ежедневная сводка настраивается в отчётах: отдельное время по дням недели, новые, решённые и оставшиеся активные проблемы. Расписание использует часовой пояс сервера. Язык серверных уведомлений задаётся главным администратором через клиент независимо от языка интерфейса.

## Настройки, сертификаты и наблюдатель

Настройки сгруппированы по функциям; поиск помогает найти ящик, Telegram, сертификат или пороги. Доверенные сети сервера и язык уведомлений меняет главный администратор. Перед изменением CIDR убедитесь, что новая конфигурация оставляет маршрут с административной машины.

Сервер использует HTTPS и подписанные настройки доверия для агентов. Перевыпуск сертификата не должен требовать переустановки агентов; следите за подтверждением версии доверия. Отпечаток нового сертификата сообщается пользователям и через настроенный Telegram. Не копируйте приватные ключи в публичный репозиторий.

Внешний PHP-наблюдатель размещается вне площадки сервера. Скачайте пакет из настроек, выберите профиль хостинга и следуйте START-HERE: приватные файлы вне public_html, heartbeat.php внутри публичного каталога, cron с нужной версией PHP. Общий ключ хранится приватно. Тестируйте доставку и пропуск сигналов; сам Telegram-бот не выполняет проверку доступности.

## Установка и обновления

Для сборки на Windows требуется SDK .NET 10; на целевой машине нужен runtime, а не SDK. PUBLISH.bat предлагает два Setup.exe, привычные папки или оба варианта. Включение установщиков runtime выбирается при публикации. Скачанные установщики Microsoft проверяются по подписи.

Обновления клиента и сервера запускаются только кнопкой «Обновления» в клиенте. Сервер обновляет главный администратор. Выпуск и пакет проверяются по ключу издателя, подписи и SHA-256. Для изменения условий лицензии требуется интерактивный установщик. Обновления агентов остаются автоматическими по их политике.

Во время обновления сервера создаётся резервная копия и перезапускается служба; закрытие окна ожидания не отменяет начатое обслуживание. Не запускайте второе обновление параллельно. При ошибке проверьте статус обслуживания и резервную копию перед повторной попыткой.

Без доверенной Authenticode-подписи Windows может показывать «Неизвестный издатель» и SmartScreen. Заполнение сведений 321.su не заменяет такую подпись. Проверка наших пакетов обновления — отдельный механизм; защита Windows не отключается.

## Начало работы: от установки до первой проверки

ЗАДАЧА
Подключить клиент к серверу и получить первую подтверждённую проверку. Клиент — рабочее место оператора; проверку доступности, сбор почты и анализ выполняет сервер. Закрытие клиента не останавливает службу.

ШАГИ
1. На Windows-сервере запустите серверный установщик с правами администратора. Укажите HTTPS-порт, адрес, доверенные частные подсети и параметры существующей или новой БД. Не выбирайте очистку при обновлении.
2. Сохраните адрес сервера и отпечаток сертификата. Для адреса вида https://192.168.1.10:7443 проверяйте именно выбранный порт, а не 443.
3. В клиенте укажите HTTPS-адрес, пользователя и пароль. Сверьте отпечаток с данными сервера по независимому доверенному каналу.
4. Откройте «Устройства», добавьте узел и укажите имя, адрес и тип. Для RouterOS используйте раздел «Коммутаторы»; одна запись не должна дублироваться в двух разделах.
5. При необходимости добавьте сервис и свяжите его с устройством. Ping подтверждает доступность адреса, но не работоспособность приложения.
6. Дождитесь серверной проверки. На главной проверьте время снимка, время проверки и состояние. Если получены только старые сведения, откройте карточку и проверьте связь с сервером/агентом.

ОЖИДАЕМЫЙ РЕЗУЛЬТАТ
В карточке есть свежая проверка. Зелёный цвет означает подтверждённое исправное состояние, серый — отсутствие достаточных данных. Если проверка ещё не выполнялась, не следует считать узел исправным по отсутствию ошибок.

ЕСЛИ НЕ ПОЛУЧИЛОСЬ
Проверьте службу сервера, адрес, порт, Windows Firewall и доверенные сети. Доступный TCP-порт ещё не подтверждает успешный TLS или вход. Ошибки сертификата устраняйте проверкой доверия; не отключайте TLS-проверку.

## Главная: состояния и действия правой кнопкой

КАК ПОЛЬЗОВАТЬСЯ
На главной четыре списка: устройства, резервное копирование, счета и коммутаторы. Каждый список прокручивается отдельно. «Все →» открывает полный раздел. Обычный щелчок открывает карточку или историю; правая кнопка мыши открывает действия именно выбранной строки. С клавиатуры используйте клавишу контекстного меню или Shift+F10 на строке.

УСТРОЙСТВА
Доступны карточка, агент, проблемы, сервисы, задания, связанные пароли, история отчётов и настроенные Web/SSH/RDP-подключения. Изменение, архивирование, повторный разбор писем и удаление требуют соответствующих прав. Связанный пароль не раскрывается без обычной проверки доступа к хранилищу.

БЭКАПЫ
История относится к выбранному заданию; при нескольких ожидаемых запусках одного задания они используют одну карточку настроек. Можно открыть связанное устройство, изменить задание, повторно разобрать письма или удалить задание. Удаление может быть запрещено сервером из-за связанной истории.

СЧЕТА
Можно открыть карточку и историю, скачать документ, отметить текущий период оплаченным, изменить или удалить запись. «Оплачено» — реальная запись операции на сервере. Снять случайную отметку можно в истории оплат. Если у записи нет сохранённого документа, скачать PDF не получится — откройте карточку и проверьте источник.

КОММУТАТОРЫ
Доступны состояние и события, интерфейсы, проверка конфигурации, обновление результатов мониторинга, свойства, правила и профиль. Это действия внутри Assistant; команды изменения RouterOS автоматически не выполняются.

ПОЧЕМУ ПУНКТ НЕДОСТУПЕН
Пункты зависят от прав на раздел. Для изменений нужны права записи; просмотр паролей и персональных данных сохраняет дополнительное подтверждение. Отсутствующий раздел запросите у администратора, а не обходите через главную.

## Устройство и агент: показатели, службы, пороги

НАСТРОЙКА
1. Создайте устройство с постоянным понятным именем. Адрес и тип задают способ базового наблюдения.
2. Откройте карточку → «Агент». Создайте установочный пакет или Linux-команду для этого устройства. Не публикуйте команду регистрации и её секреты.
3. Установите пакет на целевом узле. Сверьте имя компьютера и отпечаток ключа при подтверждении регистрации.
4. Откройте политику агента. Включите нужные проверки и задайте пороги CPU, памяти, дисков и сетевой нагрузки. Настраивайте пороги под назначение узла, а не под краткий случайный пик.
5. Добавьте критичные службы по системным именам. Название в оснастке Windows может отличаться от имени службы. На Linux используйте полное имя systemd unit, например nginx.service.
6. После сохранения сравните версию политики на сервере и применённую версию в отчёте. Изменение настроек не означает мгновенное получение нового измерения.

КАК ЧИТАТЬ ПОКАЗАТЕЛИ
Полосы дисков показывают занятое и свободное место; для Windows — том, для Linux — точку монтирования. /boot и /boot/efi имеют отдельную политику. Inode — отдельный ресурс: свободные гигабайты не исключают исчерпание inode. Память показывает общий объём и использование; сетевые показатели относятся к конкретному интерфейсу и интервалу измерения, а не к сумме за всё время.

СЛУЖБЫ И ТАЙМЕРЫ
Обычная служба должна иметь рабочее состояние. Успешный oneshot может быть inactive/dead — это не авария. Для timer проверяются активность расписания и результат связанного задания. Ошибка пакета обновления рассматривается отдельно от успешного запуска задания без пакета.

ПРОБЛЕМА НЕ ЗАКРЫВАЕТСЯ
Проверьте, что после исправления пришло свежее подтверждение, а не старый снимок. Для ручных инцидентов изучите причину и подтвердите решение; автоматические закроются по своему условию восстановления. Не удаляйте регистрацию агента ради смены цвета.

## Бэкапы: настройка двух запусков и поиск пропавшего отчёта

ПРИМЕР
Один сервер отправляет отчёт о задании два раза в день: после утреннего и вечернего копирования. Создавать два одинаковых устройства не нужно.

1. В «Резервном копировании» добавьте задание. Укажите название, систему бэкапа, устройство, дни и ожидаемые завершения, например 09:00; 21:00.
2. Укажите допуск ± минут. Допуск охватывает раннее и позднее завершение вокруг каждого ожидаемого времени. Если окна перекрываются, уточните расписание, чтобы письмо не подходило сразу нескольким запускам.
3. В почте найдите настоящее письмо этого задания. Откройте его и выберите привязку. Используйте устойчивые отличительные строки темы/тела — имя задания, NAS или защищаемого объекта. Для нескольких строк выберите И либо ИЛИ. При И должны совпасть все заданные условия; при ИЛИ достаточно одного.
4. Выберите цель-задание, сохраните правило и проверьте найденные совпадения. Не привязывайте все письма только по слову backup.
5. Убедитесь, что выбран корректный словарь результата. Привязка отвечает «чьё письмо», словарь — «успех или ошибка». Полученное письмо без распознанного результата не подтверждает успешный бэкап.
6. При исправлении словаря используйте повторный разбор писем. Просто изменение словаря не является новым отчётом от системы копирования.

НЕТ СЕГОДНЯШНЕГО ОТЧЁТА
Проверьте ожидаемый запуск, допуск и дни расписания. Затем проверьте ящик и время фактического поступления на IMAP. Посмотрите нераспознанные письма, правила привязки и результаты анализа. Вчерашний успех не закрывает сегодняшнее отсутствие отчёта. Если сломалась доставка почты, показывается отсутствие подтверждения, но это ещё не доказательство повреждения резервной копии.

ПРОВЕРКА ПОСЛЕ НАСТРОЙКИ
Сопоставьте строку текущего запуска с датой последнего отчёта и его результатом. Проверьте хотя бы один реальный успешный запуск и один безопасный тестовый отчёт с ошибкой.

## Счета: полный цикл от письма до оплаты

ДВА НЕЗАВИСИМЫХ СПОСОБА
Ручные повторяющиеся платежи продолжают работать без распознавания почты. Автоматический разбор входящих счетов дополняет их, а не заменяет.

РУЧНОЙ СЧЁТ
1. Откройте «Счета» → «Добавить». Задайте название, сумму, срок и периодичность.
2. Проверьте правила рабочих дней. По умолчанию заблаговременная оплата — зелёный статус, приближение срока — жёлтый, просрочка — красный; порог и выходные определяются настройками.
3. После фактической оплаты нажмите «Оплачено». Для повторяющегося платежа появляется следующий период; уже оплаченный сохраняется в истории.
4. При ошибочной отметке откройте карточку/историю и снимите отметку у конкретного периода. Не создавайте второй счёт для исправления одной случайной оплаты.

СЧЁТ ИЗ ПОЧТЫ ИЛИ ФАЙЛА
1. В настройках счетов укажите отдельный почтовый сбор и правила обработки. Проверьте соединение с ящиком.
2. Откройте очередь входящих счетов либо «Распознать счёт из файла». Выберите поддерживаемый документ.
3. Сверьте получателя и плательщика. ИНН/КПП из блока плательщика не должны подменять реквизиты поставщика. Проверьте номер, дату, срок, итоговую сумму, НДС и банковские счета по оригиналу.
4. Распознавание изображения может ошибаться в цифрах и разметке. Исправьте поля до сохранения; хороший внешний вид документа не гарантирует правильный OCR.
5. При необходимости настройте обучение/правило для повторяющегося формата, затем повторите проверку на другом документе того же отправителя.
6. Сохраните результат и проверьте привязанный платёж. Документ доступен из карточки и через «Скачать PDF», если он сохранён сервером.

ЕСЛИ ПОЛЕ НЕ ЗАПОЛНИЛОСЬ
Откройте оригинал. Различайте отсутствующее в документе значение и нераспознанное значение. Не подставляйте придуманные банковские реквизиты. Повторная загрузка того же документа не должна использоваться вместо исправления существующей записи.

## MikroTik: подключение, правила и анализ конфигурации

ПОДКЛЮЧЕНИЕ
1. В «Коммутаторах» добавьте MikroTik и его адрес REST/API. Используйте отдельную учётную запись с правами только чтения.
2. Для недоверенного локального сертификата сначала независимо сверьте SHA-256 отпечаток и заполните поле доверия. Сертификат CA и сертификат самого сервера — разные объекты; отпечаток должен соответствовать проверяемому сертификату.
3. Проверьте получение модели, версии, интерфейсов и свежих журналов. Наличие Ping не означает работоспособность HTTPS API.
4. В карточке MikroTik откройте «Мониторинг → Настроить правила устройства». Укажите важные WAN, uplink и корпоративные туннели.
5. Чтобы изменить или отключить правило, выберите его строку. Выпадающий фильтр «Все правила» меняет только вид списка.
6. Чтобы заменить весь набор, выберите «Профиль для замены», нажмите «Заменить из профиля…» и подтвердите. Выбор профиля сам по себе ничего не меняет. Затем нажмите «Применить» и сохраните карточку устройства.

СОБЫТИЯ
Важность, задержка и направление в Telegram задаются правилами. Новая неудачная попытка входа продлевает окно тишины от последней попытки, а не добавляет к нему ещё час. Поднявшийся важный интерфейс/туннель закрывает соответствующую проблему по подтверждённому восстановлению. Отсутствие свежих логов не является подтверждением безопасности.

АНАЛИЗ КОНФИГУРАЦИИ
Запускайте «Анализ конфигурации» и изучайте итог пути пакета, источники, интерфейс, семейство IP и рассмотренные правила. INPUT защищает маршрутизатор, FORWARD — транзит. DST-NAT изменяет дальнейший путь; правила IPsec ограничены IPsec-трафиком. Отдельное разрешение не доказывает открытый доступ, если другой применимый этап блокирует путь.

«Нужна проверка» означает неполную модель или неподдержанное условие, а не подтверждённую публикацию порта. «Игнорировать» сохраняет исключение для находки в Assistant; оно не исправляет firewall. Команды в рекомендации выполняются администратором вручную только после проверки назначения и порядка правил. Автоматического изменения RouterOS в программе нет.

ПОСЛЕ ИЗМЕНЕНИЯ FIREWALL
Повторите проверку конфигурации и убедитесь в свежем времени снимка. Для сомнительной публикации проверьте доступ извне с разрешённого тестового узла. Не отключайте общую защиту WAN ради проверки одного порта.

## Telegram: события, восстановление, закреп и сводка

ПЕРВИЧНАЯ НАСТРОЙКА
1. Создайте бота и добавьте его в нужный чат. В настройках уведомлений задайте токен и chat ID. Не отправляйте токен в переписку и диагностические архивы.
2. Разрешите боту отправку сообщений. Для закрепления в группе нужны права администратора с разрешением закреплять сообщения.
3. Отправьте тестовое уведомление и убедитесь, что выбран правильный чат.
4. Выберите группы событий и уровни важности. Настройте задержку доступности отдельно от отчётов бэкапа: задержка сетевой неисправности не должна откладывать контроль пропущенного бэкапа.

ЧТЕНИЕ СООБЩЕНИЯ
Проверьте имя объекта, источник, время возникновения, важность и подробности. Красный/оранжевый значок обозначает активную проблему, зелёный — восстановление. Повторения одной проблемы должны оцениваться вместе: счётчик и последнее время важнее количества одинаковых строк.

ЗАКРЕП
Закреп предназначен для текущих активных проблем, а не полной истории. Если бот не закрепляет сообщение, проверьте его права. Исчезновение проблемы из закрепа не удаляет историю из программы. Старое историческое событие и текущая проблема — разные сущности.

ЕЖЕДНЕВНАЯ СВОДКА
В разделе отчётов задайте время по дням недели. Учитывается часовой пояс сервера. Сводка описывает возникшие/решённые и оставшиеся активные проблемы; она не заменяет срочные уведомления о критичных событиях.

ЕСЛИ НЕТ СООБЩЕНИЯ
Проверьте выбранную группу, важность, задержку, доступ сервера к Telegram и результат теста. Затем убедитесь, что событие действительно новое/активное и не игнорируется правилом. Не создавайте искусственно сотни событий на рабочей инфраструктуре ради тестирования.

## Внешний контроль: PHP-хостинг и проверка разрыва связи

НАЗНАЧЕНИЕ
Если сервер мониторинга сам потерял сеть или остановился, он не сможет отправить Telegram. Внешний PHP-обработчик получает периодические сигналы и самостоятельно проверяет, не прекратились ли они.

УСТАНОВКА
1. Откройте настройки → «Внешний контроль сервера» → «Создать ZIP для хостинга». Выберите подходящий вариант размещения и заполните пути хостинга. Скачайте сформированный архив и его инструкции.
2. Разместите публичный receiver в public_html выбранного сайта. Конфигурацию, worker и файлы состояния разместите вне публичного каталога. Для общего хостинга домашний каталог и корень сайта могут отличаться.
3. Используйте конкретный абсолютный путь, доступный PHP на запись. Каталог состояния должен существовать или создаваться с разрешёнными правами. Не указывайте каталог чужого сайта или системный каталог.
4. Запускайте worker через актуальный PHP, выбранный на хостинге. Если cron использует /usr/local/bin/php8.4, используйте тот же исполняемый файл для init и test. Полная команда берётся из инструкции сформированного пакета.
5. Выполните инициализацию и тест отправки. Настройте cron каждые пять минут. Не считайте размещение файлов завершённой настройкой без cron.
6. В Assistant задайте HTTPS-адрес приёмника и общий секрет из конфигурации. Секрет не публикуется в URL или сообщениях.

КОНТРОЛЬНЫЙ ТЕСТ
Убедитесь, что сигнал принимается. Затем временно остановите отправку на тестовом сервере и дождитесь внешнего предупреждения. Возобновите отправку и проверьте восстановление. Не отключайте сеть рабочего ДЦ ради теста.

ЕСЛИ CRON ЗАВЕРШАЕТСЯ С КОДОМ 255
Проверьте версию PHP, полный путь к worker, синтаксис конфигурации и права каталога состояния. Запустите ровно ту же команду вручную в терминале хостинга и сохраните текст ошибки без секретов.

## Права, пароли, персональные данные и безопасная работа

ПРАВА НА РАЗДЕЛЫ
Главный администратор назначает доступ к каждому разделу. Чтение позволяет просматривать сведения; запись — изменять их. Отсутствие пункта слева обычно означает отсутствие доступа. Контекстное меню главной не предоставляет дополнительных прав.

ПАРОЛИ
Создавайте одну запись для одного секрета. Её можно связать одновременно с устройством и сервисом, не копируя пароль в несколько мест. Для просмотра/копирования открывается обычная проверка доступа. Двойной щелчок открывает запись; показ и копирование пароля — отдельные действия. Не помещайте пароль в имя устройства, URL, примечание к событию или команду запуска.

СОТРУДНИКИ И ИНВЕНТАРИЗАЦИЯ
Для персональных данных требуется отдельное подтверждение. Акты сохраняют снимок сведений на момент операции: последующее изменение оборудования не должно переписывать старый акт. Перед импортом Excel скачайте шаблон соответствующего раздела. Проверьте единицы, обязательные поля и связи; не импортируйте один и тот же список многократно ради исправления отдельных строк.

СЕАНС
Запоминание входа действует в пределах предусмотренного сеанса. Повторный запрос после разрыва связи, изменения прав или окончания сеанса защищает доступ. Это не разрешение отключать защиту хранилища. При смене пользователя завершите сеанс.

ДИАГНОСТИКА
Перед передачей журнала удалите токены, пароли, ключи и персональные данные. Сохраняйте время, имя узла, источник, идентификатор и текст ошибки. Не публикуйте целую рабочую БД как обычный диагностический файл.

## Устранение неполадок: быстрый маршрут

НЕТ СВЯЗИ С СЕРВЕРОМ
Проверьте URL/порт и службу на сервере. Затем TCP-доступность, доверенные сети, Firewall, сертификат и учётные данные — по порядку. Ping и TCP не заменяют проверку HTTPS. Если ошибка появилась после обновления, сохраните журнал установки и точную версию клиента/сервера.

АГЕНТ ДАВНО НЕ ОБНОВЛЯЛ ДАННЫЕ
Посмотрите последнее время связи, состояние службы и статус обновлятора на самом узле. Сравните версию шаблона агента на сервере с установленной. Успешное выполнение задания установки без загруженного пакета не означает получение новой версии. Не удаляйте bootstrap и ключи регистрации.

ПИСЬМО ЕСТЬ, РЕЗУЛЬТАТА НЕТ
Проверьте ящик, фактическое IMAP-время, список нераспознанных, привязку и словарь. Это разные этапы. Откройте оригинал письма: наличие слова Error с нулевым счётчиком не обязательно ошибка. После исправления правил повторите анализ.

ПОСЛЕ «РЕШЕНО» СНОВА КРАСНЫЙ
Найдите точный активный инцидент. Возможны повторный сбой, другая проблема того же устройства или отсутствие свежего подтверждения восстановления. История не должна удаляться ради зелёного индикатора. «Игнорировать» и «Решено» имеют разные назначения.

НЕ ДОХОДИТ TELEGRAM
Отправьте тест, проверьте chat ID, права бота, фильтры групп и уровней, задержку и исходящий доступ сервера. Для закрепа отдельно нужны права закрепления.

СЧЁТ РАСПОЗНАН НЕПРАВИЛЬНО
Сверьте оригинал и исправьте поля до принятия. Для PNG/скана возможны OCR-ошибки; итог, номер счета и реквизиты требуют проверки человеком.

ЧТО ПРИЛОЖИТЬ В ОБРАЩЕНИЕ
Версию программы/агента, ОС, время с часовым поясом, действие перед ошибкой, точный текст, ожидаемый результат и обезличенный журнал. Не присылайте пароли, токены или закрытые ключи. Контакт: support@321.su.

## Установка, ярлыки и управление сервером

УСТАНОВЩИК КЛИЕНТА
Выберите язык и примите соглашение. Галочки «Меню Пуск» и «Ярлык на рабочем столе» включены по умолчанию. Автозапуск выключен: при включении ярлык добавляется в общую папку автозагрузки и действует при входе всех пользователей компьютера. Настройки ярлыков сохраняются для следующего запуска установщика. Удаление клиента убирает эти ярлыки, сохраняя личные настройки и серверные данные.

УСТАНОВЩИК СЕРВЕРА
Для новой установки выберите папки, сеть и БД. Отметьте нужные ярлыки управления и открытие управления после установки. При обновлении используйте отдельный мастер: существующие пути и регистрация службы определяются автоматически. Служба запускается автоматически независимо от наличия ярлыков и открытого окна управления.

ОКНО УПРАВЛЕНИЯ
Ярлык «SysAdmin Assistant Server» запускает локальное управление с запросом прав администратора Windows. Оно показывает состояние службы, время работы, версию, HTTPS-адрес, подключение к БД, доверенные сети, отпечаток и срок сертификата. «Обновить состояние» перечитывает данные. Статус доступности БД проверяется отдельно от состояния службы: работающая служба сама по себе не доказывает исправность базы.

СЛУЖБА
Кнопки запуска, остановки и перезапуска управляют только службой Assistant. Остановка означает прекращение серверного мониторинга на это время. При активном обновлении конкурентное управление блокируется. Закрытие окна не останавливает службу.

РЕЗЕРВНАЯ КОПИЯ
Для SQLite выберите новое имя .db. Создаётся согласованная online-копия через SQLite Backup API, а не обычное копирование работающего файла. Существующий файл не перезаписывается.
Для SQL Server создаётся COPY_ONLY backup с CHECKSUM в стандартном каталоге SQL Server. Это путь на SQL-хосте, который может быть другим компьютером. После завершения окно покажет полный путь; перенос .bak на другое хранилище выполняется отдельно. У SQL-учётной записи должны быть права резервного копирования. Копия БД не включает конфигурацию сервера и сертификаты — сохраняйте их отдельно в защищённом месте.

ДИАГНОСТИКА И НАСТРОЙКИ
Диагностический ZIP содержит только разрешённые сведения о состоянии и службе. В него не включаются БД, настройки с секретами, ключи, почта и исходные журнальные сообщения. Для локального разбора можно открыть каталог данных/журналов. Сетевые настройки и уведомления меняются через клиент с правами главного администратора. Не удаляйте рабочую базу для исправления проблемы запуска.


О том, как добавить источник по письму, проверить правило и перенести его через JSON: [Источники почты](MAIL_SOURCES.md).

В разделе «Kaspersky» кнопка «Последние события KSC» открывает журнал в отдельном окне. Дважды щёлкните событие, чтобы увидеть его исходное описание и доступные сведения.
