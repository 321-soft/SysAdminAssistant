# Почтовые отчёты и хранение · 0.10.0

## Несколько IMAP-ящиков

Настройки → Почта / IMAP → Почтовые ящики IMAP. Добавляйте сервер, логин, TLS-порт, папку, пароль и режим чтения; укажите удобное название. Подключения можно отключать или удалять без удаления их событий. Только чистая установка. Пароли интеграций защищены DPAPI на сервере; клиент получает маскированные значения. Проверка соединения и диагностика описаны в MAIL_DIAGNOSTICS.md в корне архива.

Опрос последовательный, каждый ящик имеет свою блокировку; ошибки показываются в строке состояния и в диагностике почты. TLS-сертификаты проверяются; серверные письма и флаг прочтения не меняются. Идентичность сообщений включает ящик, папку, UIDVALIDITY и UID; для нестандартного порта включается порт. Изменение названия подключения не меняет идентичность. Изменение адреса/логина/папки может означать другой источник и повторный приём обычных отчётов. Ошибка одного ящика не блокирует другие; неисправное подключение задерживает цикл до тайм-аута.

## DMARC

Отдельный раздел DMARC показывает последние 500 нормализованных отчётов. При нажатии «Понятный отчёт» открывается описание с прокруткой и возможностью скопировать текст. Старые записи за пределами списка остаются в БД до выбранного срока хранения. Поддержаны агрегированные XML, XML в GZIP/ZIP, вложения MIME/EML и XML в теле. XML других корневых форматов не считаются DMARC; неподдерживаемые DMARC-форматы и повреждённые вложения требуют проверки. Forensic/RUF-отчёты и произвольный текст спама не разбираются как агрегированная статистика.

Из отчёта извлекаются домен, составитель, ID, UTC-период, политика, счётчики, IP, исходные проверки и исключения. DMARC pass определяется по согласованным SPF/DKIM в policy_evaluated, а не только по необработанным auth_results. Не прошедший поток получает предупреждение; программа предлагает проверить законных отправителей и настройки, не объявляя каждый сбой атакой. Вкладка не меняет DNS или настройки почтового сервера. Политика none и действие none не доказывают доставку письма. Данные составителя не служат доказательством подлинности самого отчёта; проверка Authentication-Results включается отдельно в настройках IMAP и использует доверенный принимающий MTA. Программа не пересчитывает подпись самостоятельно.

ID, домен, составитель и период образуют ключ защиты от дубля между почтовыми ящиками. Разные вложения одной доставки записываются в одной транзакции; отметка доставки появляется после завершения. Оригинальный XML распознанного отчёта не хранится как письмо: в историю записывается нормализованный текст, включая строки потоков. Ошибка чтения/формата остаётся в очереди.

Пределы: 32 подходящих вложения/файла, XML до 4 МБ, до 10000 строк статистики, суммарная обработка вложений до 16 МБ. DTD и внешние XML-ресурсы запрещены; файлы ZIP не извлекаются на диск, распаковка ограничена по объёму. Анализ выполняет структурную проверку нужных полей, не полную XSD-валидацию. Поддержаны обычные отчёты RFC 7489 и namespace RFC 9990. Незнакомые значения отправляются на ручную проверку.

Источники протокола: [RFC 9990](https://www.rfc-editor.org/rfc/rfc9990.html), [исторический RFC 7489](https://www.rfc-editor.org/rfc/rfc7489). Исходники XML-схемы из RFC в проект не копируются.

## Срок хранения

Настройки → Хранилище → Хранение событий: бессрочно (значение 0 по умолчанию), 30 или 90 дней. При переходе к ограниченному сроку сначала показывается количество и предупреждение; отказ не меняет настройку. После согласия настройка сохраняется и выполняется очистка. Если очистка не удалась, её повторит следующий фоновый цикл. Бессрочно не восстанавливает ранее удалённые записи.

Возраст отчёта считается от ReceivedAt, события — от CreatedAt; поэтому поздно полученный отчёт за прошлый период не исчезает сразу. Старые отчёты, сырые тексты их очереди и связанные события удаляются транзакционно. События без отчёта также очищаются по возрасту. Устройства, SQL-расписания, правила, словари, свои статьи, Vault, сотрудники, имущество и акты не затрагиваются. В базе остаются только хеши идентичности удалённых сообщений, чтобы они не загрузились вновь из IMAP. Эти хеши хранятся бессрочно и не содержат тему/тело сообщения. Письма на почтовом сервере не удаляются.

Очистка работает, пока запущен Desktop либо Worker. Worker перечитывает настройки на каждом цикле. Desktop с внешним Worker поручает автоматическую очистку ему; после изменения срока Desktop выполняет первую очистку сам. Приложения разных версий нельзя одновременно подключать к обновлённой базе схемы 4.

Свои статьи и IMAP-настройки находятся локально в settings.json; несколько клиентов общей SQL-базы могут иметь разные настройки. Срок удаления должен быть согласован между клиентами, поскольку очистка влияет на общую историю.
